# Private Native account inventory

`launcher/electron/native-account-inventory.cjs` owns one explicit selected-profile inventory transaction. Its main-only dependencies are the Native account authority, its exact profile lease, pinned wrapper/build/catalog metadata and private receipt storage. The renderer supplies only action/profile/epoch UUIDs and an explicit action boolean. Root composes IPC and UI; the leaf exports no arbitrary RPC, subprocess, path, environment or catalog-selection capability.

The transaction first acquires the authority's exact `kind:'inventory'` lease, records a create-only physical epoch lock and persists its action receipt before any native child. Each child has exactly one stdio writer and only one pending request. The method allowlist is `initialize`, `config/read`, `configRequirements/read`, `account/read`, `account/rateLimits/read` and `model/list`, with the fixed `initialized` notification. Native client-authority requests are rejected. No thread, turn, login, fork, shell, plugin or native tool RPC is available.

1. Verify exact wrapper binary/source/build pins and static build-info probe. Bootstrap bytes must match the actual pinned official `codex-rs/models-manager/models.json` SHA256 `943ca7fe1d19ed019054158303f0dbbd80b3bef43b3aa425a71aa7cb3fb52c2b`. This is source material, not account availability.
2. Run only `/usr/bin/sandbox-exec -p '(version 1)(allow default)(deny network*)(deny process-fork)' <pinned-wrapper> --account-info`. The native official auth library reads credentials. Parent reads only auth-file stat metadata. Exact ChatGPT/Codex-backend/personal-Pro-family classification is required before app-server. The accepted plan values are `pro`, `prolite` and `promax`, as defined by the pinned official protocol; the original value is preserved in account evidence. Unknown, Plus and managed plans stop here. A family classification alone never substitutes for the later ordinary-usage check.
3. Publish the closed static config through the authority's journaled expected-config-hash setter. It selects private bootstrap catalog bytes, disables tools/integrations/analytics/history, uses official provider/file auth and retains strict source policy. Start one private `--stdio` wrapper; read config layers/requirements, stable account and usage. Require native active-account-match evidence and `ordinaryUsageAllowed:true`, plus backend `accountId`. False denies usage; null is unavailable. Close and await that exact owner.
4. Under the same lease and settled auth metadata, remove only `model_catalog_json` through another journaled config publication. Start one new private online wrapper. Native immediate background model-metadata requests occur during this owned lifetime, independently of the explicit paginated `model/list`; no inference is started. Bracket model listing with account/usage and reject descriptor/account drift. Pagination is bounded to eight pages, 100 per page and 512 models.
5. Close and await the online wrapper before reading its own `models_cache.json`: upstream cache writes are ordinary, non-atomic file writes. Require fresh post-start native cache provenance, client version `0.163.0`, opaque native identity, bounded full ModelInfo instructions/capabilities, and actual picker IDs in the cache. Missing optional `tool_mode` remains missing; nothing is synthesized. Native cache may use process umask permissions inside the already private 0700 profile; metadata reads reject symlink/hardlink/foreign owner/group-writable bytes, then normalize the exact opened cache file to 0600 after process close.

`inspect()` returns receipts, account/usage/catalog metadata and **`models:[]`, `executionAvailable:false`**. `trustedInventory(actionId)` is a main-only in-memory original catalog with source/profile/epoch/cache pins; admission and capability sealing belong to the later owner. Successful inventory is neither real inference proof nor production model admission. After restart this private result is unavailable; a historical completed receipt does not reconstruct catalog authority.

Every failed/uncertain action retains a durable `unknown` receipt and cannot be replayed with its action ID. An exact child that fails physical close retains its profile lease, epoch lock and busy owner. No observation timeout silently releases that owner. Ordinary successful/failure closure removes only its own exact lock and releases the authority lease. Receipt reconciliation is passive; UI must never automatically retry a mutation. Auth-file changes are permitted only during an exact owned native app-server generation bracketed by stable public account descriptor and qualified backend account ID. After process close, changed metadata requires another network-denied personal-Pro classifier with stable metadata before advancing the baseline. Any auth change outside that interval fails unknown; no identity is silently rebound. It does not treat file stats as a defense against a hostile OS user.

## Offline after restart is deliberate

Native models are not restored automatically when the app or runtime restarts or updates. This is a decision, not an omission. Inventory accepts only `explicitUserAction:true` from the selected-profile IPC action (`explicit_inventory_required` otherwise). One run contacts OpenAI (account, usage and model metadata, including the native background model refresh) and rewrites the profile config under the authority's lease. Execution admission then starts the long-lived account process. A durable completed receipt is history, not catalog authority, so main cannot rebuild an execution from it. Until a new explicit check, `agentMode` lists no owned-native models, Native Agent tasks cannot be created, and the OAuth service has no current account authority (`oauthRegistry.reasonCode:'account_authority_offline'`).

The interface makes that state obvious and gives a one-click fix instead. `launcher/src/native-models-offline.ts` passively picks the signed-in, settled profile with the most recent inventory receipt. It ignores live logins and any held execution owner. A warning banner, "Native models are offline — Inspect account and models", appears at the top of the Agent mode Native accounts panel and in place of the generic notice in Agent tools provider authorization. The button sends the same `inspect-models` action with a fresh action ID. That action goes through the same lease, epoch lock and receipt rules, so it can never take over an owner. A lost response keeps its identity and only reconciles by receipt; it is never resent. A running check disables the button. An unconfirmed last check is shown, not retried. Focused check: `bun test tests/native-models-offline.test.ts tests/agent-oauth-service.test.ts`.

The project-config source preflight follows the exact pinned official loader: explicit `project_root_markers=[]` resolves project root to cwd, so only `cwd/.codex` is a possible project config layer. Ancestor `.git` markers are rejected to prevent checkout hooks/trust discovery. The unrelated real user's global `.codex` is neither opened nor copied. System/managed requirements and every additional effective layer require separate admission.

Focused check: `bun test tests/native-account-inventory.test.ts --timeout 5000`. It uses fake stdio children and inert executable bytes, with the build's actual official bootstrap datafile as a prerequisite; it launches no real wrapper/account/model service. One connected case covers both stages/serial ownership, no thread RPCs, exact close-before-cache, complete original metadata, duplicate-action rejection and an auth-stat race outside native ownership that retains unknown without replay, plus an authorized in-generation refresh followed by exact close and another network-denied classifier. Root owns integrated UI/source review, architecture/module-map updates and any later explicitly initiated real-account observation.
