# Interrupt hook table interleaving

The September 12 follow-up on upstream [issue #431, cause 3](https://github.com/miuuyy/codex-chatgpt-web/issues/431#issuecomment-5642829351) reports that Codex Desktop inserted a `[marketplaces.claude-plugins-official]` table between the managed command fields and its trailing `hooks.state` table. Credit to **zhaochang22** for identifying the layout and reporting that moving the foreign table preserved the parsed TOML values. This fork independently reproduced that layout using synthetic data; no upstream attachment or user configuration was required.

On baseline `72ff04ac31acbd5885eed2de76aa96bccd6cb429`, the legacy locator rejected the interleaved layout with the reported changed-after-setup error. Equivalent table placement after the trust fields already succeeded. Synthetic version 10 and version 11 TOML journals both rejected preflight, reinstall, explicit route replacement, disconnect, and uninstall; fixture files remained unchanged. The JSON trust locator already accepted a foreign table before its trust table. An existing TOML installation still needs successful ownership verification before migration to `hooks.json`, so JSON ownership support alone did not resolve this case. New installations also continue to use TOML when `hooks.json` is absent.

The change is confined to the legacy TOML locator. When its contiguous exact match is absent, a fallback requires unique, exact command and trust slices from the journal, allowing the existing line-ending normalization. It moves only the intervening table text in memory, proves that the complete parsed TOML remains equal, and checks that the parsed owned Interrupt group and trust state exactly match the journal fragment. The existing strict locator then validates the rearranged view, and its owned ranges are translated back to the original text. Removal preserves foreign table bytes and order.

Changed commands, type, timeout, trust hash, extra owned hook/state fields, malformed TOML, duplicated markers, changed group ordering, and string content masquerading as table syntax remain rejected. The fallback does not introduce a force-repair operation or alter JSON hook ownership, journal versions, or recovery behavior.

Regression coverage includes LF and CRLF, normalized line endings, existing user hooks, moved end comments before the managed definitions or inside the foreign table, preserved foreign bytes, version 10 and 11 setup/removal, migration into an existing JSON hook file, and unchanged fixture files on rejected modifications. Independent review also identified missing-final-newline inputs: removal retains one separator so a surviving marketplace table cannot concatenate with the previous assignment or disappear into its trailing comment. Both parsed semantics and source bytes are checked. The new preservation tests failed before the implementation and pass with it.

Validation on Bun 1.4.0: the focused TOML hook, JSON hook, and integration suite passed **77 tests with 600 assertions**. Root TypeScript checking and the scoped whitespace check passed. This is a local source-and-fixture result; combined release checks remain separate.

Upstream [issue #443](https://github.com/miuuyy/codex-chatgpt-web/issues/443) reports the same final error on Windows and version 5.0.6, but its issue body does not establish the interleaving cause. This change is not evidence that #443's specific installation has recovered. No live account, browser, or installed application acceptance was performed for this fixture-based fix.
