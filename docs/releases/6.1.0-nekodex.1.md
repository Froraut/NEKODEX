# NEKODEX 6.1.0-nekodex.1

This prerelease adapts upstream 6.1.0 for ChatGPT's updated web interface and includes the NEKODEX work merged since 6.0.0-nekodex.1.

## Changes

- Support ChatGPT's updated interface: the new composer and its Send/Stop controls, grouped conversation turns, assistant answer and completion detection, the new effort picker and its model view, connector mentions, and file uploads. The previous interface remains supported.
- Keep waiting while the updated interface shows Stop during a long reasoning phase before it renders the answer. The task deadline still applies.
- Close ChatGPT announcement dialogs on NEKODEX-owned automatic browser surfaces. Manual mode is unaffected.
- When ChatGPT reports that the session could not be refreshed, show "The ChatGPT session has expired. Open Browser and sign in again." instead of asking to retry later.
- Restore the window onto the display it mostly occupied, with its title bar reachable. Activity history is read by valid events, so a partial final write cannot evict it.
- Explain how to reinstall on Linux when the stable `install-launcher.sh` wrapper is missing.
- Native request validation returns typed client errors (400, 413, 415). Usage rates show `<0.1%` or `>99.9%` instead of a false 0% or 100%.
- Include the launcher UI, backend request hardening and code-structure work that shipped only in the local 6.0.0-nekodex.2 build.
- Tell ChatGPT that connected Codex Native tools act on the user's device under Codex's sandbox and approval rules.

## Downloads and trust

macOS Apple Silicon and Intel packages require Developer ID signatures, Apple notarization and stapling. Linux x64 packages use authenticated NEKODEX release metadata and GitHub build provenance.

Windows x64 remains an explicitly **unsigned preview** in the corresponding GitHub Actions run, outside trusted in-app updates. No Linux ARM64 release is claimed.

## Verification and known limits

Root and launcher TypeScript checks, the launcher build, version synchronization and the architecture map passed. NEKODEX's submission and response readers were run against upstream's captured streaming and completed snapshots of the updated interface: the grouped turns were identified, the answer was read without the user's message footer, and completion was reported only after the answer finished.

A live account turn on the updated interface was not run before publication. Upstream's Pro Limits settings-page change is not included, because NEKODEX does not ship that feature. The upstream decisions are recorded in [the 6.1 review](../reviews/2026-09-25-upstream-6.1.md).
