# NEKODEX 5.2.0-nekodex.7

Fix in-app update installation in packaged builds. Electron Builder removes the development-only `build` section from package.json; the updater now reads the persisted application identity instead. A release consistency gate prevents that identity from drifting from signing/package configuration.

Includes .6's sidebar footer: only the cat and full version number, without Source & credits or a footer link. Includes .5's Updates screen, authenticated release-feed fallback, progress and restart flow. Existing account/profile storage and connector identities are retained.

## Evidence and scope

The issue was observed during a real .5-to-.6 update attempt: downloading succeeded, but job preparation failed when reading `build.appId`. The existing app was not replaced and gateway admission was restored. Inspection of the installed ASAR manifest confirmed that `build` is absent and the persisted fork identity is present. A focused regression checks identity resolution without build metadata; the original footer was already verified in real Electron. Publisher signature, notarization and metadata gates remain enforced.

This release does not claim to fix the separately reported large-context native compaction reset. The affected task had approximately 560k input tokens; logs show an upstream 503 followed by ECONNRESET. A small real compaction succeeded, but the failing large request was not replayed and its root cause remains unresolved.
