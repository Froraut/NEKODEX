# NEKODEX 6.1.15-nekodex.1

This prerelease fixes controls that did nothing or the wrong thing, and statuses that disagreed with each other,
found in a review of every launcher screen.

## Browser and tasks

- **Sign-in guides no longer lock themselves after Retry.** Retrying a passkey or existing-Chrome sign-in kept the
  guide busy until the whole sign-in ended, so Continue, Reveal, Copy, Allow file access and Cancel stayed disabled.
- **Opening a task shows it.** "Open workspace", a tab click and Task center "Open conversation" now reveal a hidden
  ChatGPT view instead of only moving the tab highlight behind the idle screen.
- **Tabs during a sign-in.** Clicking the current tab no longer asks the main process (which refused while a
  sign-in held the account); other tabs are disabled until the sign-in ends.
- **Closing a failed or stopped task's page asks first**, as Task center already did: that page is the only record
  of how the task ended.
- "Use existing Chrome sign-in" is disabled while an embedded sign-in runs (the import was refused and the error
  blamed Chrome). "Move to front" is no longer offered on the first queued task. Zoom −, + and 100% are disabled
  at their limits. The account picker appears only when there is another account to choose. A stopped tab is
  announced as stopped, and a failed ChatGPT tab as failed. Cancelled tasks are no longer listed under
  "Needs attention" (they are drawn as quiet).

## Accounts and Overview

- **"Replace credentials" is now "Open in Browser"** on a signed-in account, which is what it did. It no longer
  re-selects the already selected account (that reset the setup verification), and it waits for the account check
  like Select does.
- Allowance cards keep their values while they are re-read, instead of all reading "not checked yet" whenever one
  account changes. The provider's retry time reads "Refresh available after …", not "Resets …". Cancellations are
  no longer listed as failures in Usage. An unavailable allowance has an amber dot, matching its badge. English
  counts no longer read "1 hours" or "1 active tasks"; limit windows use the language's own plural forms.
- Overview "Retry verification" opens Accounts when a task or sign-in holds the session, instead of doing nothing.

## Connections and shell

- **Per-account tools setup shows that account's connector**, not the proof of the account selected in the Browser.
  Its developer-mode and plugins links open in that account's own NEKODEX window rather than the system browser,
  which may be signed in to another account. Leaving Connections ends the per-account setup.
- The Local tools tab reads "Connector not verified" once the harness is set up, instead of "Not connected" beside
  two finished steps. The sidebar Connections dot follows the tabs (a degraded or failed connection is no longer an
  "Optional setup" dot). Configuring the inactive mode no longer shows the active mode's status.
- "Update available" in the sidebar no longer looks like the current page. A read-only connector name no longer
  looks like an editable field. "Return to account setup" is always available. "Refresh status" spins only for a
  refresh, finished Doctor warnings no longer pulse, and a slow start no longer repeats its status line.

## Downloads and trust

macOS Apple Silicon and Intel packages require Developer ID signatures, Apple notarization and stapling. Linux x64 packages use authenticated NEKODEX release metadata and GitHub build provenance.

Windows x64 remains an explicitly **unsigned preview** in the corresponding GitHub Actions run, outside trusted in-app updates. No Linux ARM64 release is claimed.

## Verification and known limits

Root and launcher TypeScript checks, the architecture map, the version check and the Electron shell check passed; `tests/browser-address.test.ts` covers the account-window address. The renderer preview confirmed the browser, queue, accounts, Connections and sidebar changes. The sign-in guide Retry fix is verified in code only: the preview mock does not keep a sign-in pending.
