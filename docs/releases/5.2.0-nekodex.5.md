# NEKODEX 5.2.0-nekodex.5

Update NEKODEX from inside the app instead of reinstalling a DMG for each version.

- A permanent Updates entry opens a dedicated screen with the current version, available update, download progress and speed, package verification, and restart status.
- Download and restart uses the existing signed ZIP updater, preserving accounts and settings. Active browser tasks and setup operations block installation; a task starting during download also stops the replacement handoff.
- GitHub checks fall back to its public releases feed when the anonymous REST API quota is exhausted. The fallback authenticates the release metadata with the packaged publisher trust key before offering the matching platform asset. It requires no user-supplied GitHub token and does not relax signature, version or repository checks.
- Download and installation errors remain visible in the update screen with retry controls.
- Temporary staging is correctly removed when cancelling an update whose worker has already exited.
- The new interface is translated into all five launcher languages.

This includes all reliability and localization improvements from 5.2.0-nekodex.4. Existing profiles, Codex Native4 / Zero Risk4 identities and context-limit policy are preserved.

## Focused development evidence

Renderer TypeScript and Vite bundling passed. The actual source Electron renderer displayed the permanent Updates navigation and disabled-development boundary; injected update events exercised the available, 50% download, verification and up-to-date states. This was a UI observation, not an actual application replacement.

The selected updater handoff fixture passed, including the verification phase and cleanup after an exited worker. Its first run exposed the cleanup defect, which was corrected before repeating that case. A live read-only GitHub check initially encountered an anonymous API quota HTTP 403. After the fallback was implemented, the real update controller detected published 5.2.0-nekodex.4 from a simulated current version of .3 and authenticated its metadata, without downloading or installing the application archive.

Temporary development instances were closed. No full test suite, live app replacement, or repeated passing behavior checks were run. The release workflow enforces native signatures, Apple notarization, signed metadata, asset digests and provenance attestations for both macOS architectures.
