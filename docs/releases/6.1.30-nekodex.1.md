# 6.1.30-nekodex.1

## Updates
- No second restart: after an app update NEKODEX switches to the new local runtime by itself at the next idle moment, in the same session. The previous runtime keeps serving Codex while the app is replaced, and the runtime never changes before the update is committed, so a rollback stays safe.
- The update no longer refuses while tasks run. Download and verification happen in the background; installation waits for active browser tasks to finish ("Waiting for active tasks to finish…") and never cancels them. Quitting NEKODEX during preparation cancels it cleanly.
- Update checks fall back to the signed release feed on any GitHub API failure (timeouts, rate limits) and retry once.
- Old local runtimes are removed after a successful switch (each was ~150 MB); the current, configured and one previous version are kept.
- Faster start: the packaged runtime is verified once per launch instead of twice.

## Tunnel
- Network or VPN blips no longer switch Web models off. A healthy tunnel is checked locally only, timeouts count as "unknown", and recovery backs off (15 s up to 5 min) instead of giving up after five failures.
- When the tunnel cannot reach OpenAI (VPN off, region block, DNS), NEKODEX now says so ("OpenAI unreachable — check VPN or network connection") instead of reporting ready.
- A leftover tunnel process from a previous launch is cleaned up regardless of its last recorded state; a crashed tunnel is noticed immediately.
- "Repair Web transport" reconnects per-account tunnels.
- Connector verification no longer fails with "account readiness changed while verifying".

## Native connector (tools/list unchanged)
- A tool result rejected by NEKODEX's request parser now completes the ChatGPT tool call with an explicit error instead of hanging for minutes.
- Tool calls Codex never received are cancelled after 25 s without a consumer instead of being polled until the turn times out.
- The connector releases its leases immediately on shutdown; catalog requests answer within 3 s; unconfirmed calls carry their operation id; parallel calls are batched into one Codex round.
- Broker lifecycle events are recorded in `diagnostics/turn-broker-events.jsonl`; connector log lines are timestamped.

Local app update; no public release assets.
