# NEKODEX 6.1.12-nekodex.1

This prerelease makes Codex Native6 tool calls survive long waits and finished responses, clarifies the
connector setup screen, and pins every published connector schema. The Codex Native6 connector itself
is unchanged: no new ChatGPT app is needed.

## Changes

- **Slow tool calls no longer end the turn.** Codex runs one tool batch at a time, so a call can wait
  on an approval in Codex or on an earlier call. After 80 seconds a Native5 or Native6 call now returns
  a running handle with an `operation_id` that ChatGPT polls with `codex_tool_poll`, instead of the
  transport deadline revoking the whole turn and losing the result. A dropped MCP request keeps its call
  the same way. Native4 and Manual mode keep the earlier behavior.
- **Finished answers are no longer discarded.** When ChatGPT finishes its answer but never acknowledged
  an owned tool result, NEKODEX acknowledges it after five seconds instead of failing the turn with
  `unacknowledged_async_result`. Codex already has every native result in its task history.
- **Compaction with queued operations.** A queued owned operation is cancelled before dispatch when
  Codex starts context compaction, instead of reporting the compaction instruction as its result and
  blocking completion.
- **No endless waits.** An MCP request whose process died expires after three minutes instead of
  blocking completion forever; a reconnect that redelivers the same tool batch no longer counts it
  twice; long turns reclaim old request records instead of being retired after 4,096 MCP calls.
- **Clearer results for ChatGPT.** Structured tool results are sent only as JSON objects, as MCP requires.
  Nested gateway results no longer repeat images as base64 text. A reused `operation_key` says that
  it did not run again, a stopped turn says why it stopped, and error messages keep their underlying
  cause. A successful tool result is no longer thrown away when only its bookkeeping cleanup fails.
- **Better per-turn instructions.** The prompt explains the ~90-second window, running handles,
  approval waits, one-batch-at-a-time execution, a new `operation_key` per execution and immediate
  acknowledgement.
- **Connector setup screen.** When the saved connector already is the target, step 3 no longer asks
  to create a new App ID or warns about renaming an old connector. It names the ChatGPT account being
  set up and explains that each account and workspace needs its own app with the exact name.
- **Connector verification.** A failed check lists the other Codex apps it saw, detects names that
  differ only in case, spacing or invisible characters, and explains duplicate apps. Connector
  readiness is restored for every enabled account at startup, not only for the primary one.
- **Pinned connector schemas.** The exact `tools/list` of Native4, Native5, Native6 and Zero Risk4 is
  stored in `docs/connector-abi/` and checked in CI, so a published schema can no longer change in
  place. Native6 apps created before 2026-09-27 hold older tool descriptions; see
  [connector identity migration](../connector-identity-migration.md).

## Downloads and trust

macOS Apple Silicon and Intel packages require Developer ID signatures, Apple notarization and stapling. Linux x64 packages use authenticated NEKODEX release metadata and GitHub build provenance.

Windows x64 remains an explicitly **unsigned preview** in the corresponding GitHub Actions run, outside trusted in-app updates. No Linux ARM64 release is claimed.

## Verification and known limits

Root and launcher TypeScript checks, the architecture map, the version check and the connector ABI check passed. Focused tests covered promotion at the soft deadline and on disconnect, the direct fast path, compaction cancellation, fence auto-acknowledgement, lease expiry, tombstone reclamation, capacity errors, retirement reasons, redelivered batches, structured content, and the Native6 and Native4 MCP paths end to end against a real broker. No live ChatGPT turn exercised a real approval wait, and the async tools had no recorded production traffic on the test machine before this release.
