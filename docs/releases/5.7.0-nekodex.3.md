# NEKODEX 5.7.0-nekodex.3

This update addresses the reported post-update window visibility and misleading initial download bar,
and includes the accepted findings from the additional backend, frontend and architecture review.

- Explicit open/update/restart requests foreground the macOS app. Hidden autostart remains hidden.
- A crashed launcher renderer offers native recovery while preserving account views and active work.
  The pinned Electron build can retain detached frame wrappers after a crash, so IPC protection remains
  fail-closed and recovery uses an explicitly chosen, guarded restart. Main-frame load failures have
  one bounded reload attempt; loading HTML alone is not considered recovery.
- Quit/restart stays reversible until the supervisor accepts the native HTTP/browser/compaction drain.
  Cleanup failures after that point cannot reopen a partly dismantled application.
- Download progress starts empty while size/progress is unknown. Verification and restart are shown
  as stages, without a partially filled download meter. Resumed downloads retain actual observed bytes.
- Tunnel status uses ordered revisions. An old loss report cannot overwrite a newer recovered state,
  and monitor updates are bound to the current tunnel PID. Native admission remains independent.
- Codex sign-in polling tolerates two transient failures before exposing explicit Retry. Stale account
  snapshots have an inline recovery action and block mutations until fresh state arrives.
- Connector creation guidance is a localized three-step ordered list with a separate permission note.

Focused evidence: the delayed tunnel-loss case passed; five affected renderer flows passed; an isolated
DEV launch was visible/focused; forced renderer loss produced the guarded native recovery prompt and
preserved separate account views. No full test suite was run. macOS native-control binding errors were
tracked separately from the installed application's process/runtime health.

All prior 5.7 account, Native6, statistics, recovery and README improvements are retained. Windows remains
an unsigned preview; macOS and Linux use the authenticated distribution path.
