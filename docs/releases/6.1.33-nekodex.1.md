# 6.1.33-nekodex.1

This is the first public release since 6.1.28-nekodex.1 and includes the changes from the unpublished 6.1.29–6.1.32 builds.

## Codex route and gateway

- A local gateway in front of NEKODEX is recognized: when `openai_base_url` points at a loopback gateway whose `/healthz` proves it forwards to this runtime, startup, route status, doctor and Connections → Models and Codex route show the route as active instead of "Codex bridge route is inconsistent" or "configuration differs".
- NEKODEX still never rewrites that value, so repair, reconnect and removal keep refusing until you restore the route yourself.
- After a Mac restart, startup waits up to 60 s for a gateway that comes up late, instead of rejecting the new runtime. Any other route drift still fails immediately.
- If the runtime dies while a gateway is in front of it, the fail-safe no longer reports a route error just because the gateway's upstream (NEKODEX itself) is down.
- Codex interrupts reach NEKODEX again: upgrades could leave `~/.codex/hooks.json` pointing at a deleted runtime. The hook is now refreshed to the current runtime on every route connect, without touching your route; a hook entry you edited by hand is left alone.
- A ChatGPT security-check denial is returned to Codex in a form it does not retry, so Codex no longer sends the same blocked request several times in a row.

## Updates

- No second restart: after an app update, NEKODEX switches to the new local runtime by itself at the next idle moment. The previous runtime keeps serving Codex while the app is replaced, and nothing changes until the update is committed, so a rollback stays safe.
- Updates no longer refuse while tasks run. Download and verification happen in the background. Installation waits for active browser tasks to finish ("Waiting for active tasks to finish…") and never cancels them. Quitting during preparation cancels it cleanly.
- "Check for updates" no longer has a one-minute cooldown. Every click asks GitHub again, and overlapping clicks share one check.
- If the GitHub API fails (timeout, rate limit), update checks fall back to the signed release feed and retry once. Staging now relies on the signed release metadata digest and no longer needs the unsigned checksum file.
- Old local runtimes (about 150 MB each) are removed after a successful switch. The current version, the configured version, one previous version and any version still named by a user LaunchAgent or systemd user unit are kept.
- Faster start: the packaged runtime is verified once per launch instead of twice. A runtime whose files differ from the signed package at the same version is reinstalled.

## Tunnels and network

- Network or VPN blips no longer switch Web models off. A healthy tunnel is checked locally only, timeouts count as "unknown", and recovery backs off from 15 s to 5 min instead of giving up after five failures.
- When the tunnel cannot reach OpenAI (VPN off, region block, DNS), NEKODEX says "OpenAI unreachable — check VPN or network connection" instead of reporting ready. Web requests that arrive while a tool tunnel reconnects wait for it, and report the real cause if it does not come back.
- Leftover or crashed tunnel processes from a previous launch are cleaned up, and a tunnel this launcher started stays owned even when its status probe stalls.
- A cold start after the old runtime died in the middle of an update now recovers on its own, instead of needing two manual quits.
- "Repair Web transport" reconnects per-account tunnels. Connector verification no longer fails with "account readiness changed while verifying".
- macOS: account tunnel keys can be kept in the Keychain, shared by the app, the CLI and headless restarts. Existing key files move only when you press **Migrate** and are retired only after the tunnel works with the new key; on other systems you choose unencrypted private-file storage explicitly.
- On Macs that use a TUN VPN, ordinary Quit can keep the background runtime serving Codex once you declare a background route with `setup --native-background-route DIRECT` (or an exact HTTP(S) proxy origin). This setting is available only from the CLI.

## ChatGPT pages, sign-in and Cloudflare

- Crashed or frozen ChatGPT pages reload by themselves with backoff, and a page unresponsive for 30 s is restarted. A new turn waits briefly for a recovering page and otherwise fails with "this prompt was not sent".
- When a reload cannot clear ChatGPT's Cloudflare check, Overview, Accounts and Connections say "Security check needed" and send you to Browser to tick "Verify you are human", instead of offering a Retry that only reloads the check. The warning clears as soon as ChatGPT answers again.
- Cloudflare recovery on a hidden, throttled home page is no longer reported as failed when it succeeded, and it can run again after a later challenge. It waits for running turns, sign-ins and checks to finish before reloading.
- Stuck "Verification unavailable" states recover: a session check that failed while the network or VPN was still connecting runs again on a backoff (20 s up to 10 min), and a ChatGPT page that loaded without a composer is reloaded once.
- Retry and Check account wait for an in-progress check instead of failing with "account is busy", and sign-in no longer flaps while a check is using the page.
- Account checks after launch are fast again on Electron 44; before, they could time out for several minutes because the reloaded hidden page never rendered. Accounts show "checking" instead of "Needs setup" meanwhile.
- Passkey and Google sign-in steps in embedded windows are handed to your system browser, because embedded windows cannot use passkeys. A failed passkey or Chrome session import now logs why.
- Chrome session import works for secondary accounts. Time spent on Chrome's Allow prompt no longer counts toward the import timeout, and large ChatGPT local storage (up to 64 MiB) no longer blocks the import.
- The OpenAI Platform sign-in window recovers from blank or failed loads (for example a Cloudflare HTTP 403) with an explicit Retry, and no longer breaks the login form's own navigation.
- A finished failed operation no longer leaves the Browser home page red, and stale browser errors clear after a verified sign-in.
- The Codex allowance on Accounts is read once per launch and retried after transient failures, instead of being stored as "not available".

## Replies and turns

- Formulas are returned once, as their original LaTeX (`\(...\)` inline, `\[...\]` display), instead of both the visual and accessibility copies. If a formula's source is missing or ambiguous, the turn fails rather than inventing one.
- Long answers with repeated paragraphs, headings or horizontal rules no longer fail with "changed a completed text block" when ChatGPT redraws earlier parts of the reply. Answer blocks are tracked by their live page element, so a file preview that appears, changes or disappears no longer shifts text onto the wrong block.
- Instant replies start sooner. NEKODEX skips a redundant model-menu reopen, reuses a model that is already selected on a retained page (the pre-send check still runs), and streams the final paragraph as soon as ChatGPT has finished.
- If a turn fails before its prompt was sent (a crashed page, or a tab removed by a failed navigation), Codex's own retry now goes through instead of being refused as cancelled, and the original cause is shown. Turns that were or may have been sent still point you to Task center.
- New chats keep retrying through short network drops. The model picker waits until the turn page has finished laying out before it opens.
- Message extraction ignores hidden sizing copies from the suggestion control, expands collapsed user messages, and tells older remounted messages apart from a newly sent turn.

## Local tools and the Native6 connector

- ChatGPT no longer offers plugins in Temporary Chat, so connector verification and every turn that needs local tools or the Native connector now run on a saved chat; other turns keep your Temporary Chat setting.
- As a result, tool tasks appear in your ChatGPT history, and saved memory and custom instructions apply to them. Verification itself sends nothing, so it stores no conversation.
- Manual connector approvals stay open until you answer or cancel the turn, instead of turning into Deny after 60 s. That wait does not count toward the response deadline.
- A tool result that NEKODEX cannot parse now ends the ChatGPT tool call with an explicit error instead of hanging for minutes. Calls that Codex never received are cancelled after 25 s.
- The connector releases its leases immediately on shutdown, answers catalog requests within 3 s, and groups parallel calls into one Codex round.

## Task center, diagnostics and support

- Task center puts tasks that need attention first and combines the queue with recorded tasks, with filters. Task details show send, acceptance, uncertainty and cancellation receipts, continuity across compaction, and which tools and skills a task used.
- New support report in Settings and Activity: one private file with cached runtime, task and process state, limited to allowlisted fields with per-report pseudonyms. Saving it starts no probes or repairs.
- Settings has a search box with keyboard navigation that jumps to the exact control. Connector setup has illustrated help for the selected account and mode.
- Logs give more detail: failed turns record their failure code and the chain of causes, connector and broker events are timestamped, and multi-account logs are stamped per account. Reply-alignment errors log structure only, never answer text.

## New: Agent mode and workspaces (macOS first)

These surfaces are new and still early. They are off or empty until you set them up, every tool call and remote command needs its own approval, and their screens are in English and Russian only. They target macOS in this release; Windows and Linux come later.

- **Agent mode:** create NEKODEX-owned tasks with requirements, stages and fixed turn and worker limits, run in Manual (one stage per click), Goal or Loop mode. Every stage, dispatch and outcome is recorded, and a finished stage is kept separate from a verified result.
- Agent tasks use a configured Web model or a Native Codex account that you sign in to on the official OpenAI page; Native conversations can be kept, continued and forked.
- Loop tasks take work from a mailbox, from metadata changes of one selected local file, or from an external producer through the bundled CLI. A correction keeps the current input.
- **Projects and files:** open a local folder, edit files, review Git changes, create an isolated worktree branch, and use a built-in terminal that runs your shell. Agents never type into it.
- **Remote projects:** browse and edit a selected folder on an SSH host over SFTP. Remote commands and Git changes each run only after you review them.
- **Agent tools:** set up locally installed MCP servers (with a reviewed installer that never runs package scripts), OAuth MCP providers, and selected read-only skills, including their images and PDFs. PDFs are read from the text layer only, without OCR.
- Skill scripts and Python environments built from selected wheels run in a restricted macOS sandbox.
- Apple Silicon: an offline Linux VM runs shell actions and Python or C builds; its outputs leave the VM only through a reviewed export.
- Agent tasks can make public HTTP(S) requests only to an exact origin you grant, with each request approved separately; the VM itself stays offline.
- macOS 14+: desktop control of one selected window. It is off by default and turns off again after a runtime restart.
- **Text history** (opt-in): store selected user and assistant text privately on this device, then search it, copy it or save it as Markdown. Text is not redacted automatically.
- **Codex threads** lists Codex thread metadata and can fork a thread from existing history.
- **Client usage** shows local usage for Codex, Claude Code and Gemini CLI, with cost estimates from a saved pricing snapshot. **Local API** is a read-only local control API; reading history content needs a separate permission.
- **Chrome companion** is a development extension that shares one selected tab with a local task. It is not published, so you load it unpacked in a development Chrome profile. Firefox support is not finished.

## Platform and dependencies

- Electron 44 (Chromium 152), Bun 1.4.3, TypeScript 7, Vite 8, React 19.3, playwright-core 1.64.1 and the official tunnel client SDK 0.0.16.
- MCP SDK 1.32.1 in both the runtime and the launcher, which fixes five launcher advisories (three of them high). Pinned overrides for hono, @hono/node-server, ip-address, qs, undici, brace-expansion and http-cache-semantics were updated.

## macOS release

This prerelease provides a macOS 13+ package for **Apple Silicon only**. It was built from the tagged commit on the maintainer's Mac, because the release workflow cannot yet rebuild the Native worker and execution VM that this version adds. The app and the disk image carry timestamped Developer ID signatures, Apple notarization and stapled tickets. `release-metadata.json` is signed with the fork's release key, which installed NEKODEX apps check before they update.

- Installed NEKODEX apps on Apple Silicon offer this update. Intel Macs stay on 6.1.28-nekodex.1: the updater skips releases without an Intel package.
- The metadata records a local build (`buildType: local`), so this release has no GitHub build attestation, and `install.sh` and `install-launcher.sh` refuse it. For a fresh install, use the DMG below. The README downloads stay on 6.1.28-nekodex.1, which then updates itself to this release.
- Windows and Linux packages are not part of this release; existing Linux downloads remain on 6.1.12.

The changes were tested with the repository's unit and browser-fixture tests and on the local Apple Silicon builds 6.1.32-nekodex.1 to .20. This package was checked for its signatures, notarization and the 6.1.28 updater's package checks. It was not installed through the in-app updater from 6.1.28, and no Intel, oldest-macOS or cross-platform run is claimed.
