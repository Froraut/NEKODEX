# Sixteen concurrent browser turns

The local bridge now supports up to **16 simultaneous ChatGPT Web browser turns** across Codex tasks, increased from five. The worker, session registry, and Electron tab allocator enforce the same limit. The launcher descriptions and architecture documentation reflect the new capacity.

An additional request beyond capacity is rejected without replacing an active turn. Existing duplicate-request protection, per-turn ownership, cancellation, and slot reuse remain in place. This is a local bridge capacity change; it does not increase a ChatGPT account's model or message allowances.

## Verification before release

- Three focused source checks passed: 16/17 boundary and released-slot reuse, distinct session ownership and targeted cancellation, and Electron tab allocation.
- A source-launched DEV application created 16 real idle browser surfaces and rejected a seventeenth. All probe surfaces were removed afterward.
- A separate existing-account ChatGPT Web Instant request completed successfully. It was not a 16-way live model load test and did not exercise the DEV account profile.

No sustained 16-way ChatGPT response throughput or memory-load claim is made. The release does not change model selection, account profiles, connectors, or the installed Codex route.

This macOS prerelease includes ARM64 and Intel builds, Developer ID signatures, Apple notarization, signed updater metadata, and GitHub build attestations. Windows and Linux binaries are not part of this prerelease.
