# NEKODEX 5.9.0-nekodex.1

This release combines the reviewed runtime, account and interface fixes since 5.8.0-nekodex.3.
Saved accounts, configuration and existing Native4/5/6 connector identities are retained.
Native6 remains the default for new Full setups; no new connector migration is required.

## Updates and application lifecycle

- Cancel download and preparation before installer handoff. Authenticated partial downloads remain
  available for retry; owned extraction processes finish before their staging files are removed.
- Keep startup, update preparation and exit under one transition owner, with matching busy controls.
  A Quit received during startup waits for that startup to settle. Status and cancellation remain
  available while new conflicting mutations are blocked.
- Correct resumed-download speed and ETA when a server restarts the transfer from byte zero.
- Strengthen runtime-manifest, readiness, Linux recovery and Windows process-ownership boundaries.

## Accounts, native requests and browser work

- Read an account's Codex allowance during active tasks while excluding overlapping credential and
  proxy changes. Quit can cancel and settle these read-only checks.
- Show account sign-in settlement until its lease is actually released, and prevent old quota reads
  from overwriting a newer refresh.
- Preserve consistent live, in-memory and saved proxy settings if directory durability cannot be
  confirmed after an atomic file replacement. Account settings now request durable writes.
- Keep authenticated native POST redirects visible instead of automatically replaying them, close
  rejected request bodies, and preserve the validated background proxy route without a GUI descriptor.
- Propagate cancellation through browser acquisition/preparation and compaction; bound retry/control
  retention without resetting an exhausted turn's retry allowance.
- Retire stale pending context changes and catalog messages. A saved Codex restart hint no longer
  replaces actual model-connection status.

## Interface

Accounts and Usage offer explicit retry actions. Repeated sign-in and Manual confirmation clicks
are guarded; Manual readiness, localized verification times, update cancellation and transition
locks use consistent state. Existing account sessions and the native background-runtime workflow
are preserved.

## Validation and delivery

Development evidence: 24 focused backend cases, 23 synthetic production-component UI scenarios,
two isolated Electron main/preload/renderer flows, TypeScript checks and the renderer build.
The source review and limits are recorded in [the integrated review](https://github.com/Froraut/NEKODEX/blob/v5.9.0-nekodex.1/docs/reviews/full-stack-20260921.md).
No full repository test suite or live provider account operation was used for this release decision.

macOS ARM64 and Intel packages require Developer ID signing and Apple notarization. Linux x64 is
covered by authenticated release metadata. Windows x64 remains an explicitly unsigned Actions
preview artifact, outside authenticated in-app updates; Authenticode is not provisioned.
The release workflow separately verifies package integrity, metadata signatures, provenance and
uploaded asset digests. These are not claims of live Windows/Linux installation or provider access.

Use **Updates → Download and restart** in the installed app. If the updated interface retains the
previous runtime to protect active work, finish those tasks and use **Restart NEKODEX** to activate
its new runtime. The download-cancellation action becomes available after this version is installed.
