# 6.1.33-nekodex.4

## Agent mode

- Goal tasks get an independent semantic review before they can be verified. One Web model, chosen explicitly and run in its own context without tools, reviews the whole deliverable against the request, corrections and recorded evidence. NEKODEX, not the model, decides which citations count: action receipts and worker claims never pass a requirement alone, and new evidence or corrections clear the review. Confirm stays disabled until the review passes.
- Recorded desktop property evidence can now pass Verify; it was always refused before.

## Native Codex threads

- A thread that another Codex client (for example Codex Desktop) owns can be handed off explicitly: NEKODEX uses Codex's own per-thread writer lock, sends nothing while the other client holds the thread, runs one turn, then releases it. Approvals requested during that turn are refused, and a turn whose outcome is lost is held for inspection instead of being replayed.
- A selected thread's full text history can be loaded page by page.
- Fork receipts report whether Codex carried the thread's stored attachments over.

## Browser companion

- The Chrome and Firefox companion can now send a text turn to one ChatGPT tab that you bind explicitly. The tab, signed-in account, model and effort are checked before the single send, and nothing is ever re-sent: a lost acknowledgement holds the companion until you release that operation. Turns with tools, attachments or images still need NEKODEX's own browser.
- The extension packages now carry icons and a privacy policy (local only, no telemetry).

## Desktop tools

- Pixel clicks in the selected window are no longer refused on macOS 27 because of the Dock's or the screenshot toolbar's invisible overlay windows. macOS Accessibility hit-testing now decides whether the point belongs to the selected window, and windows that do take input still block the click.
- A click or typing that waits for the window to come to the front must follow an observation that also waited for it. Otherwise it is refused at once, with a clear reason, instead of failing later.

## macOS release

This prerelease provides macOS 13+ packages for Apple Silicon and Intel, built by the release workflow, with timestamped Developer ID signatures, Apple notarization, stapled tickets, signed release metadata and GitHub build attestations. The Apple Silicon package uses the reviewed Native worker and VM guest pinned by SHA-256 in `launcher/native/release-inputs.json`. Windows and Linux packages are not part of this release; existing Linux downloads remain on 6.1.12.
