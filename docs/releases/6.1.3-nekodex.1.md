# NEKODEX 6.1.3-nekodex.1

This prerelease makes the Web models in Codex match ChatGPT's real model choices and stops Cloudflare's "Verify you are human" check from returning after NEKODEX restarts and updates.

## Changes

- **Web model names match ChatGPT.** ChatGPT has five thinking levels. GPT-5.6 Sol runs Instant, Medium, High and Extra High. The Pro level runs GPT-5.6 Sol Pro or, on plans that include it, GPT-6 Pro (powered by GPT-6 Astra). Codex now lists GPT-6 Pro (Web), GPT-5.6 Sol Pro (Web), GPT-5.6 Sol (Web) and GPT-5.6 Sol Instant (Web).
- 6.1.1 also listed "GPT-6 Astra (Web)" and "GPT-6 Astra Instant (Web)". Below Pro, ChatGPT runs GPT-5.6 Sol even when its model menu is set to Latest, so these rows only ever reached GPT-5.6 Sol. They are no longer listed. Saved tasks that use them keep working as GPT-5.6 Sol.
- The account check records GPT-6 only at the Pro level. Settings now calls the pinned Pro choices GPT-6 Pro and GPT-5.6 Sol Pro.
- **One stable user agent everywhere.** Cloudflare ties its verification to the browser's user agent, and all surfaces of an account share one set of cookies. The home page used the user agent saved during Chrome sign-in, while task tabs, sign-in views and separate browser windows used Electron's default. Passing the check on one surface invalidated it for the others, so the check came back after restarts.
- Cloudflare's check runs in a frame from another site. In such a frame the browser still reported Electron's default user agent to scripts, which did not match the user agent in the page's requests.
- NEKODEX now uses the bundled Chromium's standard user agent for every page, frame and request. It no longer contains the NEKODEX and Electron versions, so updates no longer invalidate Cloudflare verification. The Chrome user agent saved during sign-in is no longer applied, because the bundled Chromium would still report its own version. You pass one more check after installing this version.
- **The session check runs inside the ChatGPT page.** NEKODEX used to check the signed-in account with a request from outside the page. That request lacked Cloudflare's verification cookie, so every start logged "session HTTP 403" and the refused request disturbed the page's own Cloudflare state. The check now runs in a loaded ChatGPT page and returns only identity fields. It runs only when the ChatGPT sign-in cookie changes, after all parts of that cookie have been written, not on every Cloudflare cookie update.

## Downloads and trust

macOS Apple Silicon and Intel packages require Developer ID signatures, Apple notarization and stapling. Linux x64 packages use authenticated NEKODEX release metadata and GitHub build provenance.

Windows x64 remains an explicitly **unsigned preview** in the corresponding GitHub Actions run, outside trusted in-app updates. No Linux ARM64 release is claimed.

## Verification and known limits

The model names were checked against OpenAI's help article "GPT-5.6 and GPT-6 Pro in ChatGPT". Tests cover the listed Web rows, retired Astra rows resolving to GPT-5.6 Sol, family discovery on the French picker fixture, a stable user agent across updates, and a session check that never returns tokens. Root and launcher TypeScript checks and the architecture map passed.

A session imported from Chrome is a copy of Chrome's ChatGPT session. If ChatGPT ends that session in Chrome, for example after signing out there, ChatGPT also rejects it in NEKODEX ("session refresh was rejected"), and you need to sign in to NEKODEX again.
