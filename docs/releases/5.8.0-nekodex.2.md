# NEKODEX 5.8.0-nekodex.2

Fix a false `redirected` result when refreshing an account's Codex allowance. Electron's
Session.fetch returns a Response with an empty URL; the account reader previously treated that
documented SDK limitation as a redirect before processing the authenticated session response.

Both requests now reject redirects in the transport (`redirect: error`) and bypass custom protocol
handlers. The response guard accepts Electron's empty URL, still rejects a populated unexpected URL
and 3xx responses, and retains response-size, account-identity, expiry and cancellation checks.

Development verification was a manual review of this response guard and both direct callers against
the pinned Electron 41.10.7 implementation. That implementation constructs a GlobalResponse without
URL metadata and cancels requests under the error redirect policy. No new automated cases, full suite,
account changes or credential copying were run for this correction. Live provider allowance support
for the account remains a separate observation after installation.

References: [Electron net.fetch limitations](https://www.electronjs.org/docs/latest/api/net#netfetchinput-init),
[41.10.7 response construction](https://github.com/electron/electron/blob/v41.10.7/lib/browser/api/net-fetch.ts#L112),
[41.10.7 redirect rejection](https://github.com/electron/electron/blob/v41.10.7/lib/common/api/net-client-request.ts#L444).

The independent native runtime, Native6 connector compatibility and updater fixes from 5.8.0-nekodex.1
are retained. Windows remains an unsigned preview.
