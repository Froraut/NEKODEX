# NEKODEX 5.5.0-nekodex.1

Product-hardening prerelease after a manual survey of the runtime, Electron backend, renderer
and build/delivery paths.

## Statistics and daily workflows

- Separate Web browser-message and Native proxied-request reports. Native events contain no
  prompts, outputs, headers, URLs or browser-account attribution. Recording is best effort.
- Web account filters, one/seven/thirty/ninety-day reports, a full calendar including zero days,
  explicit incomplete/cancelled/unrecorded outcomes and known-outcome completion rates.
- Median/p95 observed duration and sample coverage. Native tokens distinguish reported values,
  measured zeros and unavailable data; cached/reasoning coverage is separate.
- Aggregate CSV export excludes account labels/IDs, request receipts and private content.
- Last successful reports survive transient refresh errors without crossing source/account filters.
- Exact active-tab access from Overview, keyboard-accessible dialogs/selectors, and synchronous
  protection against duplicate update installation requests. Existing progress work is integrated.

## Runtime reliability

- Full-mode broker readiness participates in health/admission; disconnected routes are no longer
  reported as ready. Login verification markers bind the exact saved state without deleting legacy
  account data. Unknown token usage is not converted to measured zero.
- Continuation state uses UTF-8 byte accounting and strict memory bounds, with explicit nonretention.
- Parallel environment/checkpoint updates merge under owned file locking. Existing thread/account
  affinity keys remain compatible; supported fallback identities gain affinity and new steering
  revisions receive their own retry budget.
- Graceful exit and update drain protect active work. Updater parent identity includes process
  identity, and external browser links require a visible native gesture plus destination checks.

## Optional Native5 long-running tools

Automatic Full mode can opt into a separate **Codex Native5** connector (**Codex Native5 DEV** for
development). Create and verify that new connector; keep Native4 instead of renaming its cached
schema. Native4 remains the synchronous default; Zero Risk4 is unchanged.

Native5 provides idempotent start keys, bounded polling, replayable terminal results and explicit
acknowledgement. Cancelling after dispatch cancels observation only; external side effects may
continue. Ownership is process-local and does not survive broker restart. Payload retention and
live-operation limits are explicit; an expired result cannot silently redispatch the original tool.

## Delivery boundaries

Development checks and their exact scope are recorded in `docs/reviews/product-hardening-20260920`.
No full suite or mass replay is part of this cycle. Synthetic observations do not establish real
account quotas, universal service reliability or absence of every possible defect.

macOS ARM64/Intel and Linux x64 use the protected release workflow. Windows x64 is a separately
labelled unsigned preview artifact until a real Authenticode publisher certificate is configured.
