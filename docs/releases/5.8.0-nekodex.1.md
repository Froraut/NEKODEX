# NEKODEX 5.8.0-nekodex.1

Native Codex now keeps its local runtime when the NEKODEX interface exits. Reopening attaches to the
same authenticated daemon instance, preserving the unified native/Web model picker and Native6
connector identity. A new **Stop connections and quit** action performs the guarded full shutdown.

- Native streams survive ordinary interface exit. Web admission closes independently and refuses
  detachment while Web work is active. Active runtime upgrades wait for a safe restart.
- Background networking retains the last validated proxy route when the launcher is unavailable;
  it never silently substitutes direct access for an unknown or failed proxy configuration.
- Closing a window with no system tray now minimizes it instead of stopping the runtime.
- The post-update foreground recovery, initially empty download meter, separate verification stage,
  ordered tunnel readiness, login retry recovery and compact connector instructions from 5.7.0-nekodex.3
  are included, alongside the earlier account allowance, official sign-in and usage improvements.

Reopen NEKODEX after changing system proxy/PAC settings. Web models need its browser sessions. The
background daemon is not an OS-managed restart service, and local native usage telemetry can miss
events while the interface is closed. Existing installations may first show **Restart NEKODEX** to
activate the new core after the updater commits the replacement.

Development evidence: one real process/stream/reattach case, one exact-proxy fallback case, a real
isolated Electron close/menu observation, type checking and a renderer build. No full suite was run.
See [architecture and evidence](../design/native-background-runtime.md) for precise limits.

macOS arm64/Intel and Linux x64 use the authenticated release path. Windows x64 remains an unsigned
preview; Authenticode is not provisioned.
