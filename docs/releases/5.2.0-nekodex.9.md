# NEKODEX 5.2.0-nekodex.9

Add **NEKODEX → Check for updates…** to the macOS application menu, matching the requested native-menu entry point. It brings a hidden launcher forward, opens the Updates screen and requests a GitHub check. The menu label follows the selected launcher language. A pending menu request survives renderer initialization without losing the user's action.

The Updates screen also retains Check for updates when a version is already available. After the existing quota cooldown it can replace an older candidate with the newest compatible release. Checks remain blocked during download, verification and installation.

Includes .7's packaged updater identity fix, the cat/full-version footer, signed release-feed fallback and verified ZIP installation/restart flow. Existing account data and settings remain compatible.

## Development evidence

The focused refresh regression and version/link checks passed. Renderer TypeScript and Vite bundling passed during native-menu development. A real isolated Electron source run invoked the actual application-menu item: the hidden window became visible and navigated to Updates. The existing available/download/progress/verification/error UI observations and updater handoff checks were reused. No full suite was run; the development process and profile were removed.

The .8 workflow was cancelled before publication so that this release includes the native-menu requirement as well as the sidebar screen. The separate large-context compaction failure is not claimed fixed.
