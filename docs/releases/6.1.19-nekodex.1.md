# NEKODEX 6.1.19-nekodex.1

This prerelease completes the unready-account handling that 6.1.18 introduced, after a full review.
The Codex Native6 connector is unchanged: no new ChatGPT app is needed.

## Changes

- **Only lasting problems fail a task.** Some account states end on their own or when the user
  resumes. Queued Web tasks now wait them out instead of failing after 45 seconds: launcher startup
  while accounts are still being checked, an account busy with a sign-in or another check, and a
  paused account.
- **The cause names the right account and the full fix.** The cause now refers to the account the
  task is pinned to, not the selected one. It names the account. It also covers missing model
  evidence, a model or level the account does not offer, and a disabled account. Each message points
  to the action that actually unblocks the next attempt (usually **Check connector**). Messages follow
  the launcher language.
- **Signing in or setting up a tunnel finishes the job.** After a sign-in, or once a new account
  tunnel is running, NEKODEX re-runs the account and connector check itself. A retry after the fix
  is then admitted.
- **Retrying after a fix works.** Codex's automatic replay still stops at once. A later attempt for
  the same turn now gets a fresh check instead of repeating the old cause.
- **Rollback stays safe.** Readiness causes are stored in a separate journal field. A 6.1.17 launcher
  can read the queue again. An unknown cause from a newer version no longer disables the queue.
- **Other fixes.**
  - Task center shows the cause and when a waiting task will fail.
  - A task paused only because its owner missed polls (for example during sleep) continues by itself.
  - A retained conversation with no owner fails at once with its own code, so compaction can fall back.
  - A tunnel problem found only at dispatch keeps its cause.
  - The Local API returns 409 with the cause instead of an uncertain 502.
