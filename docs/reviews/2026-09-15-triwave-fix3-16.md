## Result

One concrete residual state bug was fixed.

When startup synchronizes a persisted launcher state to the mode recorded in the runtime configuration, it calls `stateStore.update({ browserInteractionMode })` directly in `launcher/electron/main.cjs`. Before this correction, `state.cjs` cleared only `mcpSetupComplete` for a changed mode. Version-valid browser smoke evidence and the setup identity/timestamp fields could survive the mode transition, so the renderer could continue to display an old smoke result and old connector metadata after the mode changed.

The state store now treats every actual interaction-mode change as an account-proof transition. It clears:

- `mcpSetupComplete`;
- `browserSmokePassed` and `browserSmokeVersion`;
- `setupIdentityHash`;
- `setupVerifiedAt` and `pickerVerifiedAt`.

The existing explicit caller-side invalidation in `main.cjs` remains compatible; repeated invalidation is idempotent. The normal state merge, core-setup gate, sidebar state contract, and persisted state version remain unchanged.
