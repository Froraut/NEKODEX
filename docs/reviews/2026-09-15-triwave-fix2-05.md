## Implemented corrections

### T1-14-1 — Full DEV status keeps configuration separate from tunnel probe failure

`dev status` now records a successfully loaded configuration as `configured: true` before probing a Full-mode tunnel. A thrown `tunnelStatus()` call is captured in `mcpRuntime.detail` as `status probe failed: ...`, with `required: true` and `ready: false`. The diagnostic therefore retains the known mode and purpose while distinguishing an unreadable runtime probe from an invalid or missing DEV configuration.

### T1-14-2 — Feature-read failure no longer aborts the status report

The experimental feature read is now independently guarded. If the DEV settings/config bytes cannot be read or parsed, status still emits launcher, configuration, and MCP fields and reports `features.biggerContext: false` with a bounded `features.error`. Human-readable output says `Bigger Context: unavailable · ...` instead of claiming it is disabled or terminating before the report.

## Cross-scope review and retained limits

- The status command still takes separate point-in-time observations of the launcher descriptor, DEV config, feature settings, and Full tunnel runtime. A concurrent external edit can make those observations describe adjacent states; this lane does not invent a cross-process snapshot or locking protocol.
- The launcher `running` field remains descriptor/process evidence. It does not prove browser authentication, CDP readiness, connector attachment, or account-side Native4/Native4 DEV/ZeroRisk4 availability.
- Direct Full-to-browser-only tunnel ownership and idle-drain handoff remain owned by the setup/launcher boundary. `cli.ts` continues to await `setupDevProfile` and does not stop a foreign or busy tunnel.
- Same-name concurrent DEV chat persistence remains the previously documented optional last-writer-wins boundary; no optional redesign was introduced.
- T2-14-1's production CLI status-probe path is outside this exclusive DEV CLI scope.

Native4, Native4DEV, and ZeroRisk4 names, connector identity handling, public tool schemas, and ABI were not changed.
