# Native resilience and session diagnostics

Base: released `ed069f5` / `5.9.0-nekodex.2`. Implements the three agreed improvements after the follow-up review. This is source/development work; no new installer, release or installed-app replacement.

## Behavior

- Native aggregate usage is written to a private per-profile outbox beside the launcher descriptor. Retains at most 512 events, each at most 4 KiB, for 23 hours (inside UsageStore's 24-hour acceptance window). Records contain only the existing aggregate telemetry schema, never prompts, response text, headers or auth data. Files are written privately and atomically, with file fsync. Startup replays pending events and delivery retries every 10 seconds. Only recorded/duplicate acknowledgements remove an event; an unavailable UsageStore now returns 503. Existing event IDs preserve receiver deduplication after an ambiguous acknowledgement. Capacity/age limits and local storage errors still bound coverage; this is not an unlimited audit journal or a tool-operation replay mechanism.
- The daemon owns a bounded per-URL native proxy cache. Fresh verified routes serve without waiting for GUI IPC; refreshes are single-flight, requested after 30 seconds, and bounded to two seconds. A transient failure permits the last verified route for at most five minutes while the GUI is present. Explicit refusal, invalid route data and expired leases fail closed for subsequent requests; no direct fallback or provider resubmission was added. A failed background-route check revokes GUI-absence fallback for the responses route. Existing explicit proxy/environment semantics and proven GUI-absence transport remain intact. First-time, unprimed endpoints still require a successful resolution. Proxy changes may take the refresh interval to reach new requests; already dispatched requests are not rerouted.
- Session probes publish only fixed diagnostic codes. Overview, Accounts and Browser use localized explanations for timeout, service/network failure, refused/redirected inspection, rate limiting, missing identity, unexpected response and an unready browser. Unknown proof is not labelled signed out. The selected account can open its existing browser without invoking login, account replacement or token changes. Browser's empty state no longer recommends signing in merely because verification is unavailable. This does not claim the live provider-session problem has been diagnosed or resolved.

## Focused evidence

- Outbox owner replacement/acknowledgement, expiry, private files and sensitive-extra-field rejection passed.
- Separate Bun processes replayed one receipt through the real UsageStore: uncommitted HTTP 200 retained it; an ambiguous response after persistence also retained it; a successor's duplicate receipt removed it with one stored receipt total.
- Native transport with a deliberately unresolved GUI proxy check dispatched through the verified proxy without waiting, coalesced concurrent resolution, and stopped dispatch after explicit HTTP 403 rejection. Cache tests also covered refreshed routing, expiry and endpoint separation. Existing GUI-absence bootstrap check passed.
- Focused auth evidence, Accounts async/busy behavior and Overview rendering checks passed. Root and launcher TypeScript passed; renderer `index-DnskacUE.js` built successfully (existing chunk-size advisory remains).
- Isolated browser flow at 760 px passed: consistent Overview status, diagnostic on the selected account, navigation to its browser without login, preserved recovery notice and corrected empty state. Inspected screenshots in ignored `launcher/output/playwright/major-benefits-ui/session-diagnostics-*.png`. Temporary browser/server closed by the fixture runner. An initial assertion incorrectly expected a Browser heading; corrected to assert the actual browser recovery surface.

No live provider request, account mutation, proxy setting change, production runtime restart, broad test suite or release packaging was used. The already installed signed release remains unchanged. First-token timing and recovery/replay of side-effecting tool operations remain outside this agreed package.
