# September 14 issue, flow and alternatives investigation

Inventory refreshed 2026-09-14 11:18 UTC. Baseline: fork `80cc424` (installed 5.1.0-froraut.5); upstream `e85e369`. All **39 open issues and 26 open PRs** are accounted for below.

This report distinguishes source-confirmed defects, already integrated changes, optional proposals and symptoms that require account/platform evidence. It does not claim that all upstream reports are resolved, that a generic connector error proves a ban, or that any external safety restriction has been bypassed. Public issue bodies/comments and changed PR metadata/files were retrieved; consequential paths were inspected directly. Older unchanged items retain the evidence from the September 11–12 reviews.

## Implemented corrections in this working branch

- Pending catalog state prevents repeated installation and explains the actual desktop/model-picker step.
- Setup explicitly distinguishes models-only, pending connector and models-plus-tools. Tools are named in the sidebar; the next setup action is prominent.
- Developer-mode and Plugins/Create app links follow the current official UI. Video and upgrade details are optional help.
- Imported-session verification failures get a separate fixed recovery message instead of Chrome-connection advice; signed-in account metadata is visible only in the local setup UI.
- French stopped-thinking status is terminal only on the owned current response.
- Pro pinning respects the exact checked model row and collapsed advanced menu; contradictory version/effort descriptions cannot authorize a send.
- A retryable 503 emitted by this process may hand off the exact failed instruction to one successor native turn.
- Electron system-PAC decisions reach native passthrough and tunnel operations without proxying loopback IPC.
- Doctor warnings no longer receive a green Healthy heading.
- Internal idle data URLs no longer appear in the browser address label.

## Validation and delivery

Implemented in 5.1.0-froraut.7. Core and launcher typechecks passed. Seven selected regression cases cover proxy routing, real native-fetch proxy consumption, exact retry ownership, French terminal detection, repeated Pro selection and sanitized post-capture verification failure. One test harness assignment was corrected and only that failed case rerun. No full repository/package suite or cross-platform verification pipeline was authorized or run for this task.

The macOS arm64 app was built and delivered with a rollback copy. The pre6 packaged startup check passed; the final pre7 build adds Hermes. The refreshed Setup UI was inspected locally. The operational skill is installed and recognized by Codex. No Developer ID/notarization or Windows publisher certificate is claimed.

The added [Hermes integration](../hermes-integration.md) uses its existing Responses transport and normal tool loop. A focused parser/serializer regression exercised a function call, the tool-result continuation and foreign-session rejection. The provider was added through the installed app; its authenticated catalog returned five Web model IDs, and comparison with the backup confirmed preservation of unrelated Hermes settings and providers. This remains separate from live Hermes tool acceptance.

Live connector creation exposed an account/organization mismatch. The intended ChatGPT and Platform accounts were then confirmed, and a tunnel associated with that account and workspace was created and became visible in ChatGPT. Previous local credentials were backed up. The runtime key was replaced through the app; Codex Native3 was created and connected, and the installed app verified its availability. Hermes also resolved the named provider to its Responses transport. Live tool execution remains the final acceptance step; no blanket “all issues fixed” claim is made. See [the workflow and alternatives](../workflow-and-alternatives.md).
