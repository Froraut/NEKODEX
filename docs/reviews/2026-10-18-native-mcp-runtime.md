# Native external tools and idle-thread retirement

The macOS development target now completes a real Native -> approved official
MCP -> Native task. The protocol correction separates the read-only Native
process from proposals to execute declared external NEKODEX tools. Native itself
retains empty tools, read-only sandbox and approval policy `never`. Its fixed
developer instructions describe both six-field JSON branches, including null
fields and exactly-once argument serialization. The existing strict parser and
ToolJournal remain the authority; malformed responses are never repaired into
an executable action.

The first real attempt ended with an explicit read-only refusal and no file or
tool outcome. A later proposal had a non-null summary in the tool-request branch
and was correctly rejected before execution. Its argument object and LF were
valid; this was not an escaping defect. Those original receipts remain private
and were not replayed. The final task used a fresh Native thread.

The QA operator was this agent, not a new personal confirmation from the human.
The verified requirement is the exact file property above. It does not certify
arbitrary business work or the complete macOS program. Monetary spend remains
unknown. Global transcript recording stayed off.

The official filesystem runtime was reused from the previous pinned install,
without another package download. The isolated development harness copied only
its disabled trusted recipe into the current core configuration; code/data and
sandbox identities remain pinned. This setup does not claim a product feature
for migrating MCP installations between profiles.

Idle retirement exposed a separate pinned-upstream behavior: unsubscribe removes
the connection subscription, while the default idle unload delay is 1800 seconds.
Both owned admission paths now seal `thread_unload_delay_secs = 0`. The real
profile writer accepts only literal zero for this optional field; current
effective-config checks enforce the same value. The actual matching
`thread/closed` event or process close is still required. An unsubscribe ACK is
not physical-close evidence.

After a completed real Native turn, core shutdown finished with exit0 in about
0.08 seconds while the GUI remained alive and without manually closing the
account. Its exact offer remained completed, non-held and retired. The GUI then
exited0. The sibling-thread preservation boundary is covered by the focused
shared-pool fixture; no simultaneous live-sibling claim is made here.

Focused checks cover worker admission/unchanged privileges, strict Native result
branches, real profile publication and failed-publication reconciliation, and
shared account-thread lifecycle. The final affected TypeScript check passed.
The fixed public Codex binary and its reviewed hash did not change.

This exposed and corrected a missing continuation trigger: the original Run
loop stopped at approval, and an approved tool made the task ready without
scheduling the next offer. A fresh explicit Run now records a process-local
authorization for the exact task/family/generation/revision/owner. A matching
live tool outcome can use the existing idempotent `auto_step` sender. Manual
Step, duplicate callbacks, stale scopes, status/receipt reads, unknown outcomes,
pause/stop/correction and restart do not create or restore that authorization.
The durable Run receipt remains evidence, not restart permission. Focused
Goal/Loop and negative-path tests plus the real Goal above cover this change.

The tools panel now refreshes the selected task's pending calls and exact scope
with its status, clearing a stale selection while retaining completed receipts
for inspection. A rendered production-component fixture confirmed a write-to-
read transition, no automatic invocation, and rejection of late wrong-task or
older-generation responses.

Source `.9`, development receipts, installed `.8` and the earlier D01 migration
remain distinct. Private task/turn IDs and safe diagnostic receipts are retained
in the task workspace, not committed with account credentials.
