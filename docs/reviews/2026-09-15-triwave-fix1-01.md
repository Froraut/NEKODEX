# NEKODEX triwave fix1, wave1 lane1 — setup rollback

Baseline: HEAD `3740505b0107af9a83053fd523ae1ad30be36465`.

## Source change

Changed only `src/setup.ts`.

Rollback now restores the captured service or tunnel plist bytes and re-bootstraps that exact restored path directly with:

`launchctl bootstrap gui/<uid> <restored-definition-path>`

The rollback path no longer calls `installService(existing)` or `installTunnelService(existing)` after restoring a definition. Those installers regenerate plist bytes from the persisted config and could overwrite a pre-existing divergent plist. The existing snapshot, status, loaded-state, config-rollback, and concurrent-edit guards remain in force.

## DIDs fixed

- **T2-1-1 / P2:** fixed the confirmed rollback divergence path for both the managed service and managed tunnel service. An unchanged but byte-divergent pre-setup plist is preserved through rollback and re-bootstrap.
- **T2-5:** no source path in `src/setup.ts`; no change made.

## API handoff

- `bootstrapRestoredDefinition(path)` is private to `src/setup.ts`; it introduces no public API or ABI change.
- Service and tunnel helpers retain their existing public APIs. Their installers remain used for normal setup; only the compensating rollback re-bootstrap is coordinated locally in setup.
- Native4, Native4DEV, and ZeroRisk4 public identities and ABI pins were not changed.
- Lane handoff: parent may focus verification on failed setup rollback with an initially divergent service plist and an initially divergent tunnel plist, including the concurrent-edit and unknown-status guards. The parent owns the focused verification budget.

## Limitations

- No tests, typecheck, scripts, runtime, production, or release operations were run.
- Direct re-bootstrap uses the current macOS `gui/<uid>` launch domain and fails closed through `runChecked` if launchd rejects the restored definition.
- The existing DEV stopped-observation-to-first-mutation ownership race remains outside this lane and is unchanged.
