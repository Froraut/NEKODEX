# Wave 1 implementation, lane 09 — D16

Source baseline `3a66157`. Changed `launcher/electron/browser-helper-verifier.cjs` only; this report records the lane's manual review.

`stopChild` requests protocol shutdown and observes the exact spawned `ChildProcess` for 5 seconds, sends SIGTERM through that handle and observes for 2 seconds, then sends SIGKILL through the same handle and observes for a final 2 seconds. The protocol write no longer extends the grace period if its callback stalls. A failed signal request does not skip the remaining exit observation. If exit still cannot be observed, the verifier throws an explicit cleanup error and retains the exact handle until its later `exit`/`close` event; it never searches for or signals other processes.

An operation error remains the thrown error object, with its `operationId`; a cleanup error is attached as `error.cleanupError`. A successful operation with unobserved child exit throws the cleanup error with `operationId`. Normal successful operations return the same value after observed child exit. The verifier exports and the Native4 / Zero Risk4 connector identities and public tool ABI are unchanged. Direct browser-host callers need no new arguments; they can inspect `cleanupError` on the operation failure if they need the secondary diagnostic.

Manual diff review covered the verifier's operation result and cleanup path, the helper's SIGTERM/shutdown behavior, and direct browser-host callers. `git diff --check` passed. No subprocess, test, typecheck, benchmark, or live browser operation was launched. A process that does not exit even after SIGKILL is reported as unobserved rather than treated as successfully cleaned up; retained in-process ownership cannot survive launcher termination. This lane does not change the helper's worker-close implementation or other owners' files.
