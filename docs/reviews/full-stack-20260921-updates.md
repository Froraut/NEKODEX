# Updater/backend review — 2026-09-21

Scope: current `d6f8733` updater sources in `launcher/electron/update*.cjs`, `resumable-download.cjs`, `startup-recovery.cjs`, `runtime-install.cjs`, and `release-trust.cjs`. I also read the updater call sites in `main.cjs` to establish lifecycle coupling, without editing that shared file. No production accounts, secrets, network calls, live application, build, or test command was used; review was limited to source and diff inspection.

## Implemented findings

- **Durable runtime accepted redirecting filesystem roots.** Trigger: the versioned runtime directory or its `manifest.json` is a symlink left by corruption, manual migration, or a partial external repair. Impact: validation followed the link, so the launcher could accept a runtime outside its owned version directory; the supposed durable runtime could disappear with another bundle or read mutable external bytes. Fix: `runtime-install.cjs` now requires a real directory root and a bounded, non-symlink regular manifest before parsing. Internal manifest-declared symlinked files remain supported only when their resolved target stays inside the validated bundle.
- **Ignored HTTP Range produced misleading retry throughput.** Trigger: a partial download exists but the server answers the range request with `200` and a full body. Impact: bytes correctly restarted at zero, but speed/ETA retained the old partial as its baseline, reporting zero or distorted throughput during the restarted transfer. Fix: `resumable-download.cjs` resets the byte/time baseline and immediately publishes the zero-byte restart before consuming the full response.
- **Lifecycle fields could overwrite readiness authorization fields.** Trigger: a caller supplied extra lifecycle data named `token` or `packageTarget`. Impact: object spread order replaced the updater-established nonce/package identity in `ready.json`, causing a false rollback or weakening the invariant expected by the worker. Fix: descriptive lifecycle fields are serialized first; protected token, version, platform, architecture, PID, and package target are written last.
- **Linux recovery registration accepted line-breaking paths.** Trigger: an otherwise valid Linux install/runtime path contains CR, LF, or NUL. Impact: generated autostart desktop-entry text could be malformed or gain an injected line. Fix: Linux recovery argument quoting now rejects those characters, matching the Windows recovery boundary.
- **Updater preparation had no bounded user cancellation path.** Trigger: authenticated metadata/download or archive extraction stalls after update-install acquires the lifecycle fence but before the detached worker handoff. Impact: the UI could remain fenced for the download's one-hour bound, and synchronous extraction prevented the renderer's cancel request from running. Fix: the controller now exposes `cancelPreparation()`, propagates one `AbortSignal` through metadata and asset downloads, runs macOS/Windows/Linux extractors as owned asynchronous process trees, and yields once after staged validation before committing worker handoff. POSIX extraction uses a dedicated process group; Windows uses exact process identity plus a control-free, absolute `SystemRoot/System32/taskkill.exe` path with `/T /F`. A timed-out taskkill helper must itself reach `close` or exact PID/start-identity disappearance before another helper can start; unproven helper exit fails closed and preserves staging. Accepted cancellation publishes `cancelling`, waits for child `close` and process-tree exit before staging cleanup, preserves the authenticated cache partial, returns to `available`, and rejects the original install call with `UPDATE_PREPARATION_CANCELLED`. Once handoff begins, cancellation returns `too-late` and does not kill or undo the worker. If tree exit cannot be proven within the bounded termination window, staging is preserved and cancellation reports failure instead of racing a surviving writer. The owned-child execution and proof implementation is isolated in `launcher/electron/update-preparation.cjs`; `update.cjs` retains controller orchestration.

Focused regression cases were added in `tests/full-review-updates.test.ts` for these contracts, including partial retention, no subsequent request after metadata abort, child-stop/cleanup-before-resolution, staging preservation on unproven exit, no worker handoff after accepted cancellation, the explicit too-late result, and a real owned subprocess that must exit before the abort promise settles and must not perform a delayed staging write. Synthetic cases that intentionally preserve updater OS-temp staging or return a fake worker launch explicitly remove those exact fixture-owned roots in `finally`. Parent reported that the existing five cancellation scenarios passed; per lane instruction, the newly added real-subprocess case was not run here.

Bridge/source counter-review path note: inspect `launcher/electron/update-preparation.cjs` for owned-child spawn, exact identity, process-group/tree termination, close proof, and staging-preservation behavior. `launcher/electron/update.cjs` imports that helper and owns only the preparation state machine and worker-handoff boundary.

## Shared lifecycle integration (parent-owned)

`launcher:update-install` closes browser turn admission and awaits all of `beginInstall()` (metadata, resumable download, verification, extraction, staged validation, and detached worker spawn). During that interval the updater is absent from `currentGlobalOperation()`, and `shutdownInProgress` is still false. A concurrent restart, `before-quit`, or mutating IPC can therefore start while updater preparation owns browser admission and temporary/staged state. `recheck()` is protected only by the controller-local `pending`; it does not serialize the rest of the application. `cancelInstall(launch)` cannot cancel preparation because no `launch` exists until the worker has spawned.

The current parallel parent diff now closes this race with `lifecycleAdmission`: update-install acquires the transition owner before `beginInstall()`, the common IPC wrapper blocks non-observation handlers while that owner is held, and `requestQuit()` borrows the same owner for the handoff. Failure paths release the lease and restore turn admission; successful exit retains ownership until process termination. I reviewed this coupling without editing `main.cjs` or `lifecycle-admission.cjs`. Parent integration must allow its dedicated cancel-preparation IPC through the admission gate while the update owns the fence; ordinary mutating IPC remains blocked. The existing post-spawn `cancelInstall(launch)` remains a separate quit-failure rollback and is not exposed as user cancellation.

### Cancel-preparation API/state contract

- `cancelPreparation()` resolves `{ status: "cancelled", version }` only after the active downloader/extractor has stopped and the temporary staging root has been removed. The signed `.part` and `.identity.json` cache entries remain for retry.
- While cancellation settles, `getState()` publishes `{ status: "cancelling", version }`; after successful cleanup it publishes `{ status: "available", version }`. The original `beginInstall()` rejects with `code === "UPDATE_PREPARATION_CANCELLED"`.
- After worker handoff starts, `cancelPreparation()` resolves `{ status: "too-late", reason: "worker-handoff", version }` and performs no kill, rollback, or state change. With no preparation or handoff it resolves `{ status: "not-active" }`.
- If extractor-tree exit cannot be proven or temporary staging cleanup fails, cancellation resolves `{ status: "failed", version, message }`, controller state becomes `error`, and the install promise rejects with `UPDATE_PREPARATION_CLEANUP_FAILED`; it never removes potentially owned staging or reports successful cancellation over incomplete cleanup.

## Reviewed boundaries with no additional code change

- Release selection stays bound to the packaged repository, channel/version ordering, expected platform asset names, fixed HTTPS GitHub release paths, signed metadata identity, signed asset size/hash, and bounded downloads.
- Resumable downloads retain authenticated partials on transport/idle/overall timeout, reject mismatched ranges/compression/size/hash, and replace rather than append when Range is ignored.
- Staged application validation bounds and parses ASAR/plist/native headers without executing staged code, then binds application/runtime version, repository, platform, architecture, entrypoint, and required runtime files.
- Worker replacement journals target-specific paths, persists each rename phase, retains the previous installation through readiness, registers per-transaction login recovery, rolls back before relaunch on pre-commit failure, and does not roll back a committed replacement.
- Startup recovery sanitizes user-visible failure details, bounds cleanup/readiness waits, uses a fresh process for retry, and preserves saved settings/sign-in state.
