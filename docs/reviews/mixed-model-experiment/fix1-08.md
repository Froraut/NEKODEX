## Fixed roots

### `L08-helper-stdio`

Changed `launcher/electron/browser-helper-verifier.cjs` to track each exact spawned child independently through process `exit` and stdio `close`. `waitForExit()` now settles only after both boundaries are observed. Normal shutdown therefore retains the child and descriptor operation scope until stdio close; the forced termination retention path also releases only after both events. Reconciliation no longer treats process exit alone as sufficient settlement.

### `L08-helper-response`

Changed the helper result lifecycle so the `exit` event records the exit failure but does not reject immediately. The `close` boundary is allowed to deliver buffered stdout through readline first; a valid identified result or helper error remains primary. If no protocol result arrives by close, the recorded exit failure is surfaced. Connector names, public response shape, authorization behavior, and Native4/Native4 DEV/ZeroRisk4 identity checks are unchanged.

## Partial and cross-lane work

`L08-recovery-error` remains partial/unfixed in this lane. The accepted defect is the empty catch around `browserHost?.destroy()` in `launcher/electron/main.cjs`; that file is assigned to lane 5 and explicitly outside this lane's write scope. `startup-recovery.cjs` cannot recover an error that its cleanup callback discards before returning. Required cross-lane integration: change the lane 5 cleanup callback to retain the first browser-host cleanup failure, continue independent tray/window/control cleanup, and return or reject a bounded cleanup failure so `recoverStartupFailure()` cannot report `cleaned: true` after partial browser-host teardown. No change was made to `main.cjs` or `startup-recovery.cjs`.

## Rejected root

`L08-startup-timeout` remains rejected per the adjudication: the bounded cleanup result is recorded as `cleaned: false`, Restart creates a fresh process, and the old process is unconditionally exited in the recovery `finally`; the review did not provide concrete evidence of an actionable concurrent mutation after exit.

## Residual limitations

- This correction was reviewed from source only. The child lifecycle ordering and final-response precedence were not exercised in a runtime check because the parent reserves shared fast verification.
- A child that remains unsettled after the bounded shutdown windows is still reported as a cleanup failure and retained by its exact `ChildProcess` handle until both lifecycle events arrive. Process termination across launcher exit remains outside this module's proof boundary.
- Startup recovery remains dependent on the lane 5 integration described above for browser-host cleanup error visibility.
