## Result

All three accepted roots were fixed in the exclusive source scope. The report files are the only additional files written.

### `L10-malformed-call-record`

`toolCalls()` now identifies `function_call` and `custom_tool_call` records before any field filtering. It rejects missing, blank, or overlong `call_id` values; rejects missing, blank, or overlong tool names; and rejects a custom call whose `input` is not a string. This prevents a malformed call-shaped output from becoming an apparently successful empty-call turn and being persisted without a receipt. Function arguments retain the existing parsing and downstream declared-tool validation. Custom/freeform input remains a string and the public connector ABI is unchanged.

### `L10-broker-startup-rollback`

`TurnBroker.start()` now treats startup as transactional. On rejection it closes the server created by that attempt, clears the failed promise and removes the registry entry only if the registry still maps the socket path to this broker. Unix socket cleanup requires both successful listen ownership and a matching device/inode checkpoint. A stale socket removed before listen is not considered owned by the failed attempt, and a replacement socket cannot be removed by the rollback path. The original startup error remains the rejection; cleanup diagnostics are bounded to logging.

`startDevChatTransport()` remains compatible with this ownership model: it receives the broker only after `listen()` succeeds, so its existing cleanup closure is still created only for a successful transport start. No connector or authorization behavior changed.

### `L10-interactive-cancel`

Interactive ordinary messages and `/send-fill` now create a per-message `AbortController`. Ctrl-C aborts the active controller while preserving the existing readline close behavior when no request is active. The optional signal is threaded through `executeMessage()`, `DevChatDriver.send()`, automatic compaction, and the in-process `Request` passed to `responseRequest()`/`compactRequest()`. Existing callers that omit the signal retain the previous behavior.

## Direct-caller and compatibility review

The direct DEV callers were re-read after editing. The one-shot CLI path still calls `executeMessage()` without a signal and remains backward compatible. Existing `DevChatDriver.send(state, message, emit)` calls remain valid because the new argument is optional. The public `TurnBrokerOwner` interface, connector names `Native4`, `Native4 DEV`, and `ZeroRisk4`, external authorization flow, and custom tool freeform string representation were left unchanged.
