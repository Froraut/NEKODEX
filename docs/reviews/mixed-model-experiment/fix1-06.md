## Result

All four accepted lane 6 roots were fixed in the assigned source file. The changes preserve the selected primary-account compatibility policy, public connector schemas, connector names `Native4`, `Native4 DEV`, and `ZeroRisk4`, and external authorization behavior.

## Implemented corrections

- `L06-check-invalidation`: `checkAccount()` now invalidates capability and connector evidence before the first awaited `host.ready()`. It captures the new epoch before readiness and retains currentness checks before publishing capability or connector evidence. A readiness failure therefore cannot leave the previous check usable.
- `L06-admission-currentness`: `beginTurn()` captures the selected account’s evidence epoch before readiness and, after `host.ready()`, checks that the account still exists and is enabled, that the epoch is unchanged, and that the same account remains eligible. A stale fresh acquisition throws before `host.beginTurn()`; the existing reservation, pending-affinity, and trace-owner cleanup in `finally` releases the stale reservation. Exact retained turns and exact running continuations keep their existing ownership exception.
- `L06-login-selection`: `openAccountLogin()` records the successful selection revision, installs a pool-owned login operation before crossing the async reveal/login boundary, rechecks the selected account and revision, and releases the operation in `finally`. `currentOperation()` exposes the lease so a competing selection cannot commit while login is being started.
- `L06-balanced-evidence`: `chooseAccount()` rejects authenticated secondary accounts in balanced mode when no current capability record exists. The selected primary-account bypass remains intact, and connector evidence remains a separate predicate when a connector is requested.

## Direct-caller and compatibility review

The control server passes optional effort and connector requirements into the unchanged `beginTurn()` contract, so the added post-readiness check reuses the same pool eligibility logic without changing the request schema.
