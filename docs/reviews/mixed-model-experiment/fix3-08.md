- Lane: 8
- Scope: residual errors found in the current integrated helper and startup recovery paths after fix1/fix2

## Corrections

### `L08-helper-stdio`

`waitForExit()` now rechecks the tracked lifecycle immediately after registering its `exit` and `close` listeners. The fix1 lifecycle rewrite could otherwise observe neither event if both lifecycle flags became true between the initial fast-path check and listener registration, causing a false bounded timeout and unnecessary termination/error handling. The exact child remains owned until both lifecycle boundaries are observed.

### `L08-startup-recovery-result`

`recoverStartupFailure()` now retains the `cleaned` result across later readiness, dialog, and relaunch exceptions. A cleanup rejection or timeout therefore remains visible as `cleaned: false` even when native recovery UI also fails; a successful cleanup remains visible as `cleaned: true`. The existing bounded cleanup behavior and unconditional process exit are unchanged.

## Scope and integration

Only `launcher/electron/browser-helper-verifier.cjs` and `launcher/electron/startup-recovery.cjs` were changed for this wave. The lane-5 `main.cjs` cleanup aggregation is present in the current shared tree and was not edited. Direct browser-host callers continue to await the same operations and consume the same response shape. Connector names, public schemas, ABI, and Native4/Native4 DEV/ZeroRisk4 identities remain unchanged.
