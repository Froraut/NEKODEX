## Changes since wave1

Manual review of the actual fix1 source and direct callers found a residual cleanup precedence defect in `prepareWith` (`index.ts`). Prompt compilation or preparation could fail, then an asynchronous `broker.revoke(turnToken)` failure could replace that original preparation error. The catch block now preserves the preparation error as primary and attaches revoke failure with `AggregateError`; the local `activeToken` is cleared only after a successful revoke, so an uncertain external ownership state is not falsely treated as released.

No change was needed in `mcp-server.ts`: `withClaimedTurn` preserves action failure precedence while settling activity, and settlement remains primary only after a successful action. No change was needed in `finishBrowserOutcome`: browser outcome failure remains primary when revoke also fails, while revoke remains primary for an otherwise successful outcome.

The manual cancellation callbacks were reviewed for feedback loops. They retain the existing immediate browser cancellation plus best-effort capability revoke behavior, and `runManual` preserves its normalized cancellation or runtime error. Runtime capability publication remains after successful preparation and retirement observation. The freeform gateway JSON envelope remains an explicit design boundary.
