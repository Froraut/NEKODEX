## Changes

`withClaimedTurn` now captures action and activity-settlement failures independently. A rejected MCP action remains the primary failure; a settlement failure is attached with `AggregateError`. If the action succeeds, settlement remains the primary failure when it is the only failure. This applies to all registered tools using the helper, including `codex_tool_call` and `codex_tool_inventory`.

`finishBrowserOutcome` now captures asynchronous broker revocation failure independently. An existing browser outcome error remains primary and is aggregated with revoke failure. A revoke failure is thrown only when the browser outcome itself succeeded. The existing final-answer validation, output emission, completion bookkeeping, and retry cleanup remain after successful revocation.

## Compatibility and limits

Only the requested adapter files were changed. Public MCP schemas, connector names `Native4`, `Native4 DEV`, and `ZeroRisk4`, and external authorization behavior were preserved. The freeform generated exec gateway continues to use its existing JSON text envelope; no native nested MCP field-preservation contract was introduced.

Manual review covered the changed functions and their direct callers. No tests, typechecks, scripts, benchmarks, runtime launches, app starts, commits, pushes, or delegation were performed, per lane instructions. The shared tree contained unrelated concurrent edits in launcher and browser-worker paths; they were preserved.
