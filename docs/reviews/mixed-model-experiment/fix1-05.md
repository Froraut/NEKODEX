## Fixed roots

### L05-runtime-instance-proof

Positive MCP proof now stores `setupRuntimeIdentity` as the current supervisor identity composed from the existing `ownerPid`, `daemonPid`, and `tunnelPid` fields. In-flight proof publication captures and rechecks that identity. Snapshot publication invalidates proof when the saved identity no longer matches the current managed runtime. Launcher startup invalidates the complete proof before starting the managed runtime, so a new runtime instance cannot inherit a positive proof.

### L05-persisted-proof-schema

State normalization now fails closed when `mcpSetupComplete` lacks a valid setup contract, SHA-256 setup identity, verification timestamp, or runtime identity. It clears the dependent proof fields together. Proof writers populate the runtime identity alongside the existing contract and account/config identity.

### L05-runtime-config-invalidation

Successful DEV Bigger Context and Zero Risk Pro mutations invalidate MCP/account proof before publishing the changed state. The production queued Bigger Context `onApplied` callback uses the same invalidation path. Existing connector names, schemas, and external authorization behavior were left unchanged.

### L08-recovery-error

Startup recovery now retains a `browserHost.destroy()` failure, still attempts tray/window and `browserControl.close()` cleanup, and rejects cleanup after all independent cleanup attempts. If both browser-host and browser-control cleanup fail, the browser-host error remains primary and the control-close error is appended.

## Update cancellation correction

The update-install IPC caller now awaits the Promise-returning `cancelInstall`. If cancellation cleanup fails after `requestQuit` already failed, the original quit failure remains the primary message and the cancellation failure is appended.

## Residual limitations and required cross-lane integration

- Runtime identity uses the supervisor's existing process identity fields; this lane did not edit `runtime-supervisor.cjs`. A supervisor recovery that changes ownership without a subsequent launcher snapshot or proof operation is outside this lane's observation point.
- The renderer still consumes the backend snapshot's `mcpSetupComplete`; the backend snapshot reconciliation is the integration boundary that supplies the fail-closed state.
- The update controller implementation is owned by another lane; this lane only updated its direct caller to await the Promise contract.
- Parent lane should review the combined state schema and ensure concurrent edits to `main.cjs`, `state.cjs`, and `update.cjs` are merged without dropping the new proof identity, invalidation calls, or awaited cancellation.
