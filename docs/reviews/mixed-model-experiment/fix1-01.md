## Result

Fixed all three accepted roots: L01, L02, and L03.

### L01 — launchd print status is fail-closed

Added one shared exact absence classifier in `src/process.ts`. `getServiceStatus` and `getTunnelServiceStatus` now treat only the recognized `Could not find service "..." in domain for system/user` response as unloaded. Any other nonzero `launchctl print` result raises an error, preserving the existing public status schemas and preventing setup, doctor, CLI, stop, restart, or uninstall from interpreting permission, malformed-state, transport, or other errors as an absent service.

### L02 — daemon status probes are bounded

`getServiceStatus` now passes a five-second default timeout to synchronous `launchctl print`. The daemon unload poll passes the remaining enclosing deadline, capped at the status timeout, so one synchronous probe cannot bypass the poll deadline. Tunnel status already had a bounded probe; its unknown-result classification is now aligned with the daemon path.

### L03 — launchd mutations are bounded

Daemon bootstrap, bootout, and start/install mutations now use a 20-second synchronous timeout. The retrying daemon bootstrap also caps each attempt by its remaining operation deadline and retains the last failure. Tunnel bootstrap and bootout now pass the same bounded timeout alongside their existing abort signal. Existing restart/stop compensation paths continue to preserve the primary mutation failure and any resume failure.

## Residual limitations

- A nonzero `launchctl print` response whose text does not exactly match the recognized absence form remains unknown and fails closed. This is intentional; the local schema has no room for an `unknown` field without an ABI change.
- The synchronous timeout bounds the parent-side `spawnSync` wait. It does not prove that a non-cooperating external `launchctl` process or launchd mutation has completed after timeout.
- The fixed mutation timeout is a per-command bound. There is no cross-function shared deadline across a complete stop/restart sequence; unload polling remains separately bounded.
- No runtime, installed-app, launchd, account-side connector, or authorization state was claimed or verified.
