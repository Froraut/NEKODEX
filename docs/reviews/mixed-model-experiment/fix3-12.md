## Corrections

### `L12-retry-handoff-cancel`

`fix1`/`fix2` treated the call to `emit("response.failed", ...)` as delivery even when the bridge had already closed or the controller enqueue had failed. Since `emit` previously returned no status, the retry handoff callback could commit a successor claim without a failure frame accepted by the SSE stream. `emit` now returns whether the frame was enqueued, and retry publication runs only on a successful failure-frame enqueue.

The non-streaming path also published the handoff before constructing the final response JSON. It now builds the response first and records the retryable handoff only after that failure representation is available for return.
