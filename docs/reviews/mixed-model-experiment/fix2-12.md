## Residual correction

### `L12-retry-handoff-cancel` — partial correction

`fix1` moved retry-handoff creation after the streamed `response.failed` translation, but the same normal terminal path then called its cleanup callback. That callback aborted the request, and the request abort handler cleared the handoff that had just been published. The result was that a correctly delivered retryable 503 could lose its successor authorization during ordinary terminal cleanup.

The correction marks the retryable terminal publication as committed before cleanup and makes request-abort revocation conditional on that commitment. The bridge now invokes the publication callback immediately after the `response.failed` frame is enqueued and before terminal cleanup/reporting. Cancellation before that boundary still revokes the pending handoff; cleanup after the boundary no longer revokes the handoff that was already delivered.

## Actual changes since wave start

- `src/server.ts`: added a request-local retry-handoff commitment flag; request abort clears a pending handoff only before commitment; the retryable terminal callback records commitment before storing the guarded handoff.
- `src/bridge.ts`: reordered the existing terminal callback so retry-handoff publication follows `response.failed` enqueue directly and precedes terminal cleanup/reporting.
- `src/event-queue.ts`: no change in wave 2; the wave 1 current-buffered-byte accounting, cancellation discard, abort delivery guard, count limit, and streaming 32 MiB limit remain in place.

## Integration requirements

- Preserve the paired `server.ts` and `bridge.ts` ordering: a cancellation before `response.failed` delivery must revoke the handoff, while normal cleanup after that delivery must not.
- Keep the streaming queue byte total limited to bytes currently retained in the buffered array; dequeue and cancellation must release/reset that total rather than accumulate stream length.
- Parent integration must retain unrelated concurrent edits and separately inspect the shared atomic-write/symlink compensation and absent-target safeguards called out in coordinator notes; those paths are outside lane 12 ownership and were not changed here.
- Public connector names, schemas, and caller signatures remain unchanged; the new bridge callbacks remain optional for existing direct callers.
