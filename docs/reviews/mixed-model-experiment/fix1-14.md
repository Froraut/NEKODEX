## Fixed behavior

Both manual cancellation entry points now use the same exact-owner cancellation path.

- Manual tab close asks the launcher-owned runtime to cancel before releasing the tab. A successful callback acknowledgement records the local terminal cancellation and releases that exact tab.
- Authenticated `/v1/manual/cancel` starts the same runtime cancellation and returns the existing synchronous response shape with `status: "pending"` while the exact tab remains owned. The asynchronous callback releases it only after acknowledgement.
- A rejected or unavailable cancellation records a failed cancellation state, publishes a bounded user-facing message, retains the browser tab, and leaves the owner available for recovery. `endManualTurn` cannot release a tab while cancellation is pending or failed.
- Repeated cancellation while pending returns the recoverable pending result. Connector names, public connector schemas, and external authorization behavior were not changed.

Cross-process runtime acknowledgement and concurrent helper behavior still depend on the existing runtime supervisor contract.
