# Implementation wave 1 lane 11 — state proof invalidation handoff

Baseline: `3740505b0107af9a83053fd523ae1ad30be36465` (`HEAD`).

Changed source path: `launcher/electron/state.cjs`.

## Contract implemented

- `createStateStore().update()` now invalidates `mcpSetupComplete` whenever `browserInteractionMode` actually changes. The incoming mode remains the selected mode, while a fresh MCP verification is required for the new mode.
- `createStateStore().invalidateAccountProof()` is the explicit account-transition invalidation API for account selection, logout, and a failed selected-account connector check. It clears `mcpSetupComplete`, `browserSmokePassed`, and `browserSmokeVersion` in one persisted state update.
- `MCP_PROOF_INVALIDATION` and `ACCOUNT_PROOF_INVALIDATION` are exported for caller paths that need to compose the same contract without duplicating field names.
- `setupVerifiedAt`, `setupIdentityHash`, `setupContract`, and other proof metadata are retained as historical evidence. Clearing the current flags prevents that historical evidence from being treated as current readiness.
- Native4, Native4DEV, ZeroRisk4 identities, and public ABI/schema fields were not changed.
