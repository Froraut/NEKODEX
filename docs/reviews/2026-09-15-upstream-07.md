# Upstream lane 7 — large-context transport

Reviewed 2026-09-15 against NEKODEX `359d8fc` source and [coding iterations](2026-09-15-coding-iterations.md). Live GitHub issue bodies and PR file patches were fetched with `gh api`; this is a source review, not a NEKODEX runtime test. Four distinct proposals are represented by five numbers: #472 says it closes #471, though both were still open when fetched, so the design and implementation are counted once. #461 is stacked on #460 and its cumulative diff must not be read as an independent TXT implementation.

This is a credible transport optimization, not an observed NEKODEX failure or proven NEKODEX speedup. If implemented, preserve the exact envelope, bind before submit, retire on turn exit, fail closed on incomplete reads, keep the reader read-only, and count the full context in usage. Do not import patch wholesale into the modified local broker/harness. |

A fresh-chat rule changes retained-turn economics and must be reconciled with NEKODEX lifecycle before any adoption. Prefer a separate opt-in design evaluation; do not replace multipart based on the PR's reported Pro recall alone. |

Priority: investigate #427 only if repeated static text is material on retained turns; it is the clearest current source gap. Consider #472/#471 for large ordinary Full turns if measured composer latency justifies the new MCP lifecycle; its read-only safety shape is more appropriate than generic tool dispatch. Evaluate #460/#461 as a separate opt-in TXT path only after actual account/file/connector behavior is observed. The current Bigger Context path already offers large-context multipart transfer, so none of these upstream patches is a blanket correctness fix.

The [coding-iterations review](2026-09-15-coding-iterations.md) reports no long-history latency, heap or IPC benchmark and explicitly limits its UI fixture proof. No test, installation, release, or NEKODEX runtime observation was performed in this lane.
