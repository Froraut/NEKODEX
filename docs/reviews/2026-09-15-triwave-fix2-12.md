## Applied wave2 correction

Closed the remaining cross-scope browser-surface race in the renderer.

- `LauncherShell.enqueueBrowserSurface()` now serializes the optional `showBrowser()` operation together with `setBrowserSurfaceActive()` (around `App.tsx:545-555`).
- The queued show is performed only while its navigation intent is still current. If the user navigates to Settings, Activity, MCP, or another non-browser surface while activation is pending, the later layout effect queues the current `false` state behind the in-flight native operation. The browser cannot remain active because the stale show finishes before that queued deactivation.
- `activateBrowser()` now uses this same queue for its `show` path (around `App.tsx:640-644`). The existing intent check and serialized boolean surface transitions from wave1 remain intact.
- Existing wave1 fixes were preserved: browser surface commands are last-intent-wins; stale command failures do not overwrite a newer navigation error; manual-tab status changes depend on the selected tab ID rather than `manualState`; MCP wizard state is published only after `setMcpStep()` succeeds; committed MCP setup advances after a metadata-refresh failure while reporting that refresh error.
