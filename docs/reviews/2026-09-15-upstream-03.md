## Narrow follow-up and multi-account correction

The separate [lane 11 report](2026-09-15-upstream-11.md) identified #459's background-tab selection defect. `browser-host.cjs:2411-2415,2429-2435` now changes `selectedTabId` only when `reveal` is true, for reused and new Automatic tabs. The lease still returns its exact `surfaceId`/`tabId`, and `syncViewVisibility()` keeps the user's chosen tab on screen. Manual turns still select their own tab at `browser-host.cjs:2142-2146`. This was reviewed at source level only.

The multi-account edge is now corrected in source. The aggregate descriptor uses the **selected** host's account/partition/home `surfaceId` while merging every host's `surfaceTargets` (`launcher/electron/account-pool.cjs:115-139`). Thus setup's `/v1/session/inspect` account identity (`src/launcher-browser-host.ts:392-399`) and default page target (`:266-277`) refer to the same selected session; ongoing turns still use their exact lease surface IDs through the union. `selectAccount` rewrites the descriptor after the saved selection and restores the previous selection/descriptor if publication fails (`account-pool.cjs:180-193`). Account creation first publishes a selected-account home identity with no target until the new host is ready, preserving existing turn targets but failing closed for the new home (`:123-149`); successful addition republishes it, and failed-add removal republishes the previous selected host (`:159-178`). During startup, a saved nondefault selection waits for that host descriptor rather than publishing default as home; `ready()` performs final publication after both initial hosts settle (`:24-39,74-77`). The selected host owns the mode transaction (`:295-298`), so its target-mode descriptor feeds the aggregate before setup reads it. No account, connector, or Windows runtime was exercised.
