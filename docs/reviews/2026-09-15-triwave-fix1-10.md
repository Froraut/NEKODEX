# Triwave fix 1, lane 10 — renderer App handoff

Baseline: NEKODEX `3740505b0107af9a83053fd523ae1ad30be36465` (`HEAD3740505`).

## Implemented source corrections

- **T1-13-1:** `McpSurface.move()` now awaits `setMcpStep()`, applies the returned persisted state, and only then advances the local wizard step. A rejected persistence IPC therefore leaves the mounted wizard on its prior step.
- **T2-13-1:** successful `setupMcp()` is treated as the committed operation. The follow-up metadata refresh is isolated from the setup path, so a failed refresh reports an error while the wizard still advances through the persisted step transition.
- **T2-13-2:** the active manual-tab handoff effect now depends on the active tab identity. A status-only change on the already selected tab no longer redirects Settings, Activity, MCP, or another surface to Browser.
- **T3-13-1:** browser-surface IPC requests are serialized in renderer order and tracked by a monotonic intent. Navigation away invalidates earlier intents; delayed completions cannot run stale `showBrowser()`, bounds setup, sidebar reopening, or stale error reporting. The existing boolean `setBrowserSurfaceActive(active)` IPC contract is unchanged.
