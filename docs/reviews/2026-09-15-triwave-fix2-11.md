## Change made

`preflightCodexIntegration()` now calls:

```ts
readJournal({ reconcileInactiveHook: false, repair: false })
```

Preflight is a validation step before setup writes. It now observes journal state without copying missing journal files, reconciling divergent copies, or attempting pending JSON-hook recovery. This prevents the setup preflight phase from mutating shared Codex integration state between its file snapshot and the later installation call.

The existing wave1 changes remain intact:

- `readCodexSubagentProtocol()` uses `repair: false`, keeping model/protocol discovery observational.
- `inspectCodexIntegration()` uses `repair: false`, keeping route status and doctor inspection observational.

The explicit lifecycle callers retain their intentional policies. `deactivateCodexIntegration()` and `uninstallCodexIntegration()` continue to opt into `reconcileInactiveHook: true` for the proven active-primary/inactive-recovery transition; `installCodexIntegration()` and `activateCodexIntegration()` retain their existing lifecycle behavior and inactive-hook guards.

## Interaction and ABI review

- The change is caller-local and does not alter journal formats, hook ownership predicates, route values, connector names, tool schemas, tunnel contracts, or public ABI.
- `Codex Native4`, `Codex Native4 DEV`, and `Codex ZeroRisk4` remain unchanged.
- The D07 ordinary-read boundary is preserved: inspection, protocol discovery, and setup preflight do not perform journal or hook repair.
- The explicit recovery path remains separate from observational reads, so a later setup preflight cannot silently consume the recovery behavior reserved for disconnect/uninstall.

## Remaining limits

- T2-10-2 remains a confirmed conditional race in the compensation writer: an unguarded journal path can be restored from an old snapshot when a guarded sibling write aborts before that journal path was written. Its owner is `src/codex-integration-journal.ts` / `src/codex-integration-shared.ts`, outside this lane's exclusive source scope; no caller-only change can make that rollback atomic.
- The explicit uninstall path still has a cross-file observation/removal gap if a noncooperating actor inserts an identical managed hook after the final absence check and before the last recovery-journal removal. The current byte and journal guards fail closed for changed or foreign content, but identical bytes do not carry writer provenance. Closing that gap requires a broader ownership/locking design and was not forced here.
