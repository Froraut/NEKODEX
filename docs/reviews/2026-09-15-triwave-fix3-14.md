## Concrete correction

Fixed the remaining exit-status regression in `tunnelCommand`.

The current wave-2 guard correctly made `tunnel status` failure-closed for terminal-owned configurations and runtime-health-based for launcher-owned configurations. Its added `else if (serviceProbeFailed)` nevertheless made `tunnel stop` return exit code 1 whenever the post-stop service status probe threw, even though stop is explicitly exempt by the adjacent `action !== "stop"` condition and the prior lane handoff preserved that contract.

The redundant branch was removed. A successful stop therefore remains successful when the independent diagnostic service probe is unavailable; the emitted JSON still carries the structured service error. Start and restart still fail when the service/runtime result is unsuccessful. Status still reports JSON before applying its ownership-aware exit result.
