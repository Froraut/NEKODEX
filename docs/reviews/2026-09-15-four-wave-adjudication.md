## Rejected, deferred, and overclaimed paths

- **Reject `R1-14-1`:** `src/tunnel.ts:384-398` composes profile command from runtime command, mode contract and broker socket; it contains no connector `appName`. `connectTunnel` and `tunnelServiceDefinition` likewise carry no retired ChatGPT connector name. An app-name-only migration therefore cannot leave the alleged retired name in unchanged YAML. `R2-14` identifies the missing data path. Reopen only with a specific generation-dependent profile field, not health/readiness speculation.
- **Reject `R1-7-3` as a core-readiness defect:** DEV `coreSetupComplete` means valid installed configuration; `mcpSetupComplete` is separately cleared on failed Full tunnel start. DEV has no Responses daemon by design. A resolved non-ready status without a demonstrated reachable state is insufficient to add another defect.
- **Defer `R2-1-1` / R1 lane 1's optional schema checker concern:** `command-escalation.ts` evaluates a narrow JSON Schema subset. Unknown `contains`/`minItems` constraints could cause false local acceptance or rejection for a *future/unknown* card, but the outer native validator remains authoritative. This is no demonstrated approval bypass or current exact-card failure. Clarify claims of “exact” local compatibility; do not change the public approval schema on speculation.
- **Defer `R2-8-1`:** Manual Zero Risk4 deliberately follows the selected visible account. Explicitly choosing B can split Manual and Automatic task histories; without a violated Manual ownership contract this is a continuity/UX decision, not a defect. `R2-9-1` is a qualification of auth wording, not a new failure path.
- **Defer `R2-13-1`:** helper preflight rejection without `turn_settled` plus failed Abort write can reserve an ID, but the current direct caller validates its SHA-derived IDs/key and duplicate maps before dispatch. A malformed external/mixed protocol producer is required; no ordinary current-build trigger was shown. R1-13's “always settles” wording applies only after controller registration.
- **Deduplicate `R2-16-1` into D06:** same smoke evidence root through same-process IPC snapshot; the R1 claim that remounting a renderer necessarily resets evidence is false. **Do not claim a mandatory backend smoke gate was bypassed.**
- **Deduplicate** `R2-7-2` into D03, `R2-3`/`R2-4`/`R2-14` setup rollback repetitions into D01/D02, and R2 lane 5/11/15 repetitions into D10/D18/D14/D07. The nested `shell_command` option loss D09 is separate from nested error-flag loss D08.
- **Other optional boundaries:** custom cached connector identity needs a new App ID/name; full schema loading, native approval, long-running retained tasks, installed-app/account transition, helper congestion and tunnel unload timing were not proved by these source reports. A healthy server or saved flag alone is neither a completed account integration nor evidence of a runtime failure. None justifies ABI/name changes.
