## Accepted paths rechecked

- **T3-16-1 / late browser-smoke completion:** `browser-smoke` captures the
  account-proof generation, interaction mode, and setup identity before the
  helper await. It refuses to publish `browserSmokePassed` when a connector
  migration, account transition, logout, mode change, or runtime invalidation
  advances the generation or changes the identity.
- **T2-16-1 / late MCP verification:** both the Manual-mode and automatic
  connector paths recheck the same proof context immediately before publishing
  positive MCP proof. The required core-setup condition also prevents a late
  verification from restoring readiness after setup invalidation.
- **T1-16-1 / stale setup-core gate:** automatic setup rereads committed state
  after the asynchronous authentication probe and before consuming smoke
  evidence, so the pre-await snapshot is not used as the final gate.
- **T3-12-1 / interaction-mode transition:** both mode-transition callers
  invalidate account-bound proof before changing mode; the state store also
  invalidates MCP proof when the committed mode changes.
- **T3-12-2 / selected-account connector-check failure:** a failed check for
  the account still selected invalidates and publishes global account-bound
  proof. A failed check for an account that is no longer selected does not erase
  proof belonging to the newer selection.
- **T2-12-1 and T2-12-2 / account selection and logout:** both transitions
  retire the proof generation before their asynchronous browser operations and
  clear the persisted proof fields.
- **Runtime migration/startup failure:** connector migration and runtime
  failure/not-configured branches retire the generation before or with their
  readiness invalidation, preventing an older asynchronous positive writer from
  restoring proof.

The Native4, Native4DEV, and ZeroRisk4 identities, connector names, public
tool/API schemas, and ABI pins remain untouched.
