# Four-wave implementation wave 1, lane 06

Frozen baseline `3a66157`. Exclusive source writer: `launcher/electron/main.cjs`. Manual diff review only; no test execution, typecheck, packaging, installation, or publication.

## Changes

- **D03:** Each catalog monitor owns an epoch, supervisor reference and in-flight probe. Replacement or stop retires older probes. After the awaited health fetch, a probe rechecks epoch, supervisor, core/catalog/pending-context state and the exact serialized current config before persisting a positive result. A retired probe cannot stop the replacement monitor.
- **D04:** The positive catalog count is accepted only if `runtimeSupervisor.catalogHealthIsCurrent(config, health) === true` for that same fetched payload. Lane 15's synchronous helper binds service, version, mode, status, launcher ownership and owned daemon PID. No second health fetch is made.
- **D06:** Removed the independent session smoke latch. Snapshots and core setup's smoke gate derive their result from `browserSmokePassed` and `browserSmokeVersion` for the current app version. A generation-4 migration's existing persisted smoke invalidation is therefore visible to same-process snapshots. Renderer state reconciliation remains lane 12's responsibility.
- **D13:** Failed or external production startup retires the monitor and explicitly clears current MCP evidence alongside core/catalog readiness. Lane 16's state store additionally applies conservative invalidation whenever core is false; DEV's installed-config core semantics remain separate from tunnel readiness. Historical/failed startup presentation remains with lanes 12 and 13.

## Cross-lane contracts and limits

The exact call from main is `runtimeSupervisor.catalogHealthIsCurrent(config, health)` with the original received `/healthz` payload; it must remain synchronous and return a boolean. `stateStore.update({ coreSetupComplete: false, ... })` clears current catalog, picker and MCP readiness under lane 16's update policy. No public tool schema, App ID, ABI pin or native mode was changed.

This is source implementation plus manual diff review, not a live account/catalog reproduction. Parent owns the single shared focused verification pass and integration review. No extra helper or test file was added.
