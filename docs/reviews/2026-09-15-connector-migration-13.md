# Connector identity migration — lane 13: account ownership and readiness

Scope: read-only source review of `account-pool.cjs`, `browser-host.cjs`, and `main.cjs` against the coordinated Codex Native4 / Codex Native4 DEV / Codex Zero Risk4 rename. The existing #487 triage in `2026-09-15-upstream-01.md` explains why the old connector schemas remain legacy. Zero Risk3 was never published here; it is a defensive legacy alias, alongside Zero Risk2 and older names. No runtime or account operation was performed.

## Findings

- Saved account identity is independent of connector name. The pool loads account IDs from the account registry and a SHA-256 conversation/task-key-to-account map from `account-affinity.json` (`account-pool.cjs:13-34`). Browser partitions are determined by production/development profile and account ID (`browser-host.cjs:379-389`). A connector rename should not delete or rewrite account registry, affinity, partitions, cookies, or saved login state.
- Per-account connector readiness is **process-local**. `this.connectors` starts empty (`account-pool.cjs:19`), is set to the exact verified connector name by `checkAccount(..., true)` (`:209-226`), and is cleared on authentication refresh, failed inspection, or logout (`:228-260`). It is not persisted. On a new process, additional accounts require a fresh connector check before they are eligible for a connector-bound turn (`:316-323`); the default account is deliberately exempt from this pool gate. This is expected, not a saved-readiness migration.
- A **live-process rename can make the Settings readiness badge stale**: `accountSnapshot()` reports `connectorReady: this.connectors.has(account.id)` (`:94`) without comparing the stored verified name with the host's current `connectorName()`. `chooseAccount()` does compare exact names for non-default accounts (`:321`), so such an account will be excluded from new connector-bound turns even while Settings says ready. Parent fix, if connector names can change without restarting the launcher: report readiness only when `this.connectors.get(account.id) === host.connectorName()`, and clear or reverify the old claim when applying the new runtime identity. Do not copy old-name readiness into the new name.
- Active and retained automatic browser leases are intentionally exact-identity-bound. `connectorIdentity` is stored on each new tab (`browser-host.cjs:604-633`), and reuse requires equality plus `connectorBound` (`:2322-2329`). `beginTurn()` rejects the same trace with changed connector metadata (`:2365-2374`), while a retained turn under the new identity fails with `retained_conversation_unavailable` (`:2336-2343,2426-2431`). The pool pins existing traces/conversations and persisted affinity to their account before checking a retained tab (`account-pool.cjs:292-307,370-390`). Therefore do not relabel an old Native3/Zero Risk2 tab as Native4/Zero Risk4 or move its conversation to another account. Let in-flight old turns finish; new-identity continuations need a fresh matching browser conversation, with an explicit unavailable result for exact retained requests.
- `main.cjs` stores launcher setup readiness separately from per-account connector readiness. Successful verification records `mcpSetupComplete`, `setupContract`, verification time, and a hash of runtime config/account label (`:652-673`). On an updated runtime, `preserveSetup()` receives `upgrade.connectorMigrated || upgrade.tunnelProfileMigrated`; when preservation fails, main clears `mcpSetupComplete` and resets the guide (`:1328-1347`). The hash includes `appName` (`upgrade-readiness.cjs:6-13`), and `preserveSetup()` also rejects migrations (`:15-18`). Parent should ensure the generation4 identity change is surfaced as `connectorMigrated` (or a changed `appName`) so old setup verification is invalidated. In the DEV path `main.cjs:1298-1324`, Full-mode setup may remain saved until its explicit DEV doctor/verification path; inspect that parent-owned state transition when integrating the rename. Manual mode marks local runtime healthy without proving ChatGPT connector selection (`main.cjs:651-668`), so its saved setup state must not be described as new connector verification.

## Recommendation to parent

Preserve account data and leases. Invalidate old connector readiness claims and old launcher setup verification; verify the new name explicitly. The only likely source fix in these three parent-owned files is the `connectorReady` comparison for a live name change, plus ensuring the DEV/setup state reports the migration accurately. No lane-13 code changes are required for saved accounts or lease identity semantics.

Review method: direct manual source inspection only. No tests, runtime launches, account changes, commits, dependencies, or version changes.
