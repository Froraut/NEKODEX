## Findings

### 1. Medium — reduced motion suppresses the visible transform but leaves pointer tracking work active

- **Screenshot/trigger:** move the pointer rapidly across the large cat mark in `01-overview-ready.png`; repeat with OS reduced motion represented by `20-reduced-motion.png`.
- **Source:** `BrandMark.tsx:31–38` performs `getBoundingClientRect()` and three inline custom-property writes on every `pointermove`. `nekodex.css:49–53` consumes those properties as transforms. `nekodex.css:440–443` disables the visible transforms in reduced-motion mode, but the pointer handler itself remains active. `BrandMark.tsx:13–30` also changes React state once when the reaction begins.
- **Observed rendering:** both static Overview captures have stable geometry and preserve the cat silhouette. No visual reduced-motion regression is visible in the still images.
- **Source inference:** reduced-motion users should see no tracking transform because the later media rule forces `transform: none`; however, pointer movement can still force repeated layout reads and DOM style writes that no longer produce visible feedback. Under ordinary motion, doing the layout read on every pointer event may create uneven feedback on high-polling devices.
- **Unverified live behavior:** actual pointer event frequency, frame pacing, compositor behavior, and Electron performance were not measured. This is a source-backed performance/resilience risk, not an observed live stutter.
- **Minimal fix:** cache bounds on pointer entry (refresh via resize/leave), retain only the latest pointer coordinates, and coalesce the three property writes into one `requestAnimationFrame` callback. If `prefers-reduced-motion` matches, skip pointer tracking and reaction state changes entirely. Keep the current direct-DOM frame path; do not move continuous motion into React state.

### 2. Medium — the decorative cat creates a keyboard focus stop without an action

- **Screenshot/trigger:** keyboard-tab through the Overview hero containing the large NEKODEX cat in `01-overview-ready.png` or through another non-small `BrandMark`.
- **Source:** `BrandMark.tsx:49–66` gives every non-small mark `tabIndex={0}` and `role="img"`, starts a reaction on focus, and has no click or keyboard activation behavior. `nekodex.css:47` provides a visible focus ring, so this is an intentional, perceivable tab stop rather than an invisible implementation detail.
- **Observed rendering:** the cat works well as product identity in the sidebar and connected-workspace card. The still image does not communicate an action associated with it.
- **Source inference:** keyboard users can land on an image that only animates. That adds friction to navigation and makes the focus ring look like an actionable control even though no action is available. It can also trigger decorative motion merely by traversing the page.
- **Unverified live behavior:** tab order and screen-reader announcement were not exercised in live Electron, so the exact surrounding focus sequence is unknown.
- **Minimal fix:** keep the cat and its pointer personality, but remove `tabIndex`, `onFocus`, and `onBlur` when it has no product action; retain `role="img"`/label only when the image conveys useful identity. If a future cat action is intentional, render a real button with one named action and a stable hit area instead of making the image itself ambiguously focusable.

### 3. Medium — the shared switch presents a 32×18 control target unless a larger wrapper delegates activation

- **Screenshot/trigger:** toggle “Bigger Context (experimental)” in `17-context-dialog.png`, or a Settings switch near the lower edge of `13-settings.png`, especially with motor imprecision or at a scaled display setting.
- **Source:** `styles.css:2125–2145` defines `.switch` as exactly `32px × 18px`, while the dialog row is visually much larger (`styles.css:2670–2681`, minimum 56px). The visible thumb is only 14px. Nothing in the five-file review establishes that the full row delegates click/keyboard activation to the switch.
- **Observed rendering:** in the dialog capture, the switch reads clearly as the state control but occupies a small area at the far right of a wide setting row. The modal itself is stable and legible, and the row provides ample space for a larger target.
- **Source inference:** if only the `.switch` element is interactive, its target is materially smaller than the surrounding row and smaller than a robust 44px minimum target. If the full row is already an associated label, the practical pointer target may be adequate; that cannot be proven from these files.
- **Unverified live behavior:** hit testing, label association, Space-key behavior, focus trap, focus return, and state announcement were not tested in live UI.
- **Minimal fix:** make the entire 56px setting row an explicit label/action surface for the switch while retaining the compact visual track, or wrap the switch in a minimum `44×44` hit box. Keep one focus target, show `:focus-visible` around the combined row, and preserve native approval/account boundaries; this control should only change the already-scoped local preference.

## Specific polish recommendations

1. **Use one motion controller for cat feedback.** Preserve the approved cat artwork and current reaction vocabulary, but route pointer tracking through one rAF-coalesced controller, use `--duration-micro`, `--ease-enter`, and `--ease-exit` instead of local `160ms/180ms ease-out` values, and short-circuit all decorative reactions under reduced motion. `CatTail.tsx:12–51` is the right performance model: refs plus direct SVG updates, visibility suspension, and no per-frame React render.
2. **Give the context dialog a stronger interaction hierarchy without changing its content.** Make the full toggle row the target, lift its focus/selected state with the existing lavender border token, and keep the Close button secondary. A subtle opacity/translate entrance may use `--duration-panel` for ordinary motion; reduced motion should present the final frame immediately. This is a subjective polish preference grounded in `17-context-dialog.png`, where the compact switch and similarly toned nested surfaces make the primary interaction quieter than the surrounding explanation.
