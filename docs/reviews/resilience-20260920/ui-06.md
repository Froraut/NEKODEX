## Findings

### 1. High — the exact target connector identity is not reliably visible or distinguished from the current connector

**Observed rendering.** In `07-native6-setup.png`, the row labelled **Connector
name** appears blank or unreadable; no exact identity such as `Codex Native6 DEV`
can be recovered from the screenshot. This directly conflicts with the preceding
instruction to “Use the exact name below.” The capture therefore cannot support a
user copying or visually checking the required identity.

**Source inference.** `McpSurface` renders only one generic connector-name row from
`snapshot.connectorNames[interactionMode]` (`launcher/src/App.tsx:1969-1972`). It
does not label that value as the **required new connector**, show the currently
saved connector beside it, provide a copy action, or fail closed when the value is
empty/unpainted. The synthetic fixture supplies `"Fixture connector"`
(`launcher/tests/fixtures/ui-preview.cjs:57-63`), so the blank-looking capture is
rendering evidence, not proof that the runtime snapshot is empty. Settings does
show a separate current connector string (`launcher/src/App.tsx:2352-2354`), but
that distinction is absent in the wizard where the user creates the connector.

**Failure trigger and impact.** During a Native4/5-to-Native6 migration, or while
configuring the isolated DEV identity, the user reaches step 3 and cannot clearly
compare the existing connector with the exact required target. They may open
ChatGPT, rename/reuse the old App ID, create the wrong mode identity, or attempt to
verify an unrelated connector. That would blur the deliberate ABI and account
boundary even though the underlying source still keeps the identities distinct.

**Precise fix suggestion and owner.** The parent UI/lifecycle owner should replace
the generic row with an always-visible identity card:

- `Current saved connector: Codex Native4 DEV` (or `None`);
- `Create this new connector: Codex Native6 DEV` with a dedicated **Copy exact
  name** button;
- a short fixed warning: **New App ID required. Do not rename the old connector.**

If the target identity is empty, render an explicit error and disable external
create/verify actions. The target must continue to come from the runtime-provided
mode identity rather than a user-editable field. This preserves the Native4/5
schemas and prevents identity substitution.

### 2. High — “Verify runtime” does not say what is being verified or preserve the account/approval boundary in the action itself

**Observed rendering.** The primary CTA in `07-native6-setup.png` is **Verify
runtime**, while the active task is **Attach the ChatGPT connector**. The screen
does not show a pre-verification state such as “New Native6 connector created,” an
expected connector name in the CTA, or separate local-runtime and ChatGPT-connector
statuses. The paragraph mentions permissions, but that boundary is embedded in a
long block of body copy far from the button.

**Source inference.** On step 3 the primary button is enabled whenever the surface
is not busy and calls `verifyMcp()` immediately; its label comes from the generic
`copy.verifyRuntime` rather than the available Native6-specific “Verify connector”
copy (`launcher/src/App.tsx:1815-1827`, `2013-2029`; `launcher/src/i18n.ts:1603-1611`).
The UI does not state whether verification checks the exact connector identity,
the expected Native6 tool schema, the selected ChatGPT account, or only local
reachability.

**Failure trigger and impact.** A user opens Developer mode or Plugins but has not
yet created/selected the exact new App ID, then presses **Verify runtime**. A failure
will be hard to route, while a generic success presentation could be overread as
proof of Native6 schema availability or permission approval. The screenshots and
mock API cannot establish what live verification actually checks.

**Precise fix suggestion and owner.** The parent UI owner should label the action
with its exact target, for example **Verify Codex Native6 DEV connector**, and show
three separate states above it: **Local tunnel ready**, **Exact ChatGPT connector
not verified / verified**, and **Codex approvals remain unchanged**. After the
action, show the verified connector name and schema generation returned by the
backend; do not infer success from local setup alone. Keep command/edit approval
decisions in native Codex and never describe connector verification as granting
permission.

### 3. Medium — the initial Setup screen hides the Native6 recommendation until after the user enters the optional MCP path

**Observed rendering.** In `05-setup-new.png`, the lower section is titled **Codex
tools (MCP)** and marked **Optional**. Its partially visible row says **Simulated
tools over MCP** and **Continue tools setup**, but the screen does not mention
Native6, the exact target connector, the new-App-ID requirement, or the difference
between models-only readiness and Native6 tool readiness. The stronger Native6
guidance appears only after navigation to the MCP surface.

**Source inference.** Setup deliberately labels automatic MCP setup optional and
renders a generic `McpSurface` entry (`launcher/src/App.tsx:1662-1679`). Settings,
however, presents `Native6 · Recommended` and chooses among configure, upgrade,
and verify based on current connector state (`launcher/src/App.tsx:2352-2372`).
This makes the recommendation and current-versus-target distinction depend on
which screen the user happens to visit.

**Failure trigger and impact.** A new DEV-profile user completes sign-in and profile
initialization, sees MCP as optional, and leaves Setup without learning that
Native6 is the recommended connector for Codex tools. Later Settings introduces an
“upgrade” concept that was never established during setup, increasing the chance
of treating models-only readiness, local MCP installation, connector creation, and
connector verification as the same outcome.

**Precise fix suggestion and owner.** Keep models-only use genuinely optional, but
make the choice explicit in the Setup row: **Codex tools via Native6 — recommended
for file, command, and edit tools**; show the target identity `Codex Native6 DEV`
and a secondary line **Models-only mode works without this connector**. Use the
same current/recommended state model and terminology in Setup, MCP, and Settings.

## Polish recommendations

1. **Convert the step-3 paragraph into a short checklist.** This is a subjective
   hierarchy preference grounded in `07-native6-setup.png`: the dense six-line
   paragraph makes the irreversible identity rule easy to miss. Use three visible
   items—enable Developer mode, create a new connector with the copied exact name,
   then return to verify—and keep the “new App ID / do not rename” warning outside
   the collapsed upgrade disclosure.
2. **Give the identity value stronger visual weight than the field label.** This is
   subjective polish, not a confirmed accessibility failure. Use a high-contrast
   monospace value, enough padding for the full name, visible keyboard focus on the
   copy control, and wrapping rather than truncation at narrow widths. Screenshot
   inspection alone cannot establish contrast ratios, keyboard behavior, screen
   reader output, or zoom/reflow compliance.

## Evidence limits

- No live ChatGPT connector was opened, created, selected, or verified.
- No account identity, App ID, discovered tool schema, native approval dialog, or
  command/edit action was observed.
- The captures prove only the synthetic rendered states listed above. Source review
  supports control-flow and copy inferences, but does not prove runtime behavior.
- Responsive states, localization, focus movement, keyboard operation, reduced
  motion, screen-reader announcements, and post-verification success/error states
  remain unverified in this lane.
