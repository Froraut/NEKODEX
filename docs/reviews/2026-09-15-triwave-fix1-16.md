# NEKODEX implementation wave 1, lane 16 — process-tree handoff

Baseline: `3740505b0107af9a83053fd523ae1ad30be36465` (`HEAD`). Read `docs/reviews/2026-09-15-triwave-review3-15.md` and the lane 15 wave-one/wave-two reports before deciding whether the residual tunnel ownership finding fits the exclusive source scope `launcher/electron/process-tree.cjs`.

## Disposition

No source change was made in `launcher/electron/process-tree.cjs`.

The residual ownership root is already owned by `launcher/electron/runtime-supervisor.cjs`:

- `runTunnelCommand` creates each tunnel control `ChildProcess` and owns the timeout, abort, pipe-error, SIGTERM, SIGKILL, and final rejection decisions (`runtime-supervisor.cjs:1794-1945`). It currently has no supervisor-level in-flight registry or post-rejection reconciliation obligation.
- The T2-15 pipe-error path is also local to `runTunnelCommand`: it settles immediately after one termination request and does not retain the child for the bounded escalation used by timeout/abort.
- T3-15-1 is a stale-owner recovery cancellation path. `stopStaleOwnedRuntime` must pass `startSignal` through `waitForKnownTunnelStatus` and `runTunnelStopCommand`; that signal propagation and the stale-recovery state ordering belong to `runtime-supervisor.cjs`, not the low-level process-tree helper.

`process-tree.cjs` has no context for those lifecycle states. It receives only an exact child handle and an optional signal, then performs the existing owned-group operation: POSIX uses the child PID's detached process group, Windows uses `taskkill` for that PID tree, and invalid termination is reported to the caller. Adding a registry, pipe/timeout/abort callbacks, exit/close settlement, or tunnel-operation serialization here would either duplicate supervisor ownership or change the helper's public behavior without resolving the caller's missing state transitions.

The current helper therefore remains the correct low-level primitive for the requested bounded escalation and exact-child targeting. It does not perform broad process-name kills and its exports/identities remain unchanged.

## Handoff

The actionable implementation belongs in `launcher/electron/runtime-supervisor.cjs`, with the smallest safe correction consisting of:

1. retaining each tunnel control child until terminal `exit`/`close` observation, including the pipe-error entry path;
2. preserving the bounded SIGTERM/SIGKILL escalation and cancellation error as the primary diagnostic while retaining an unresolved-child obligation after the deadline; and
3. propagating the stale-owner `startSignal` through tunnel status/stop calls so cancellation cannot continue the stale recovery operation.

Those changes were outside this lane's exclusive write scope. No tests, typechecks, scripts, runtime/production actions, or commits were performed.
