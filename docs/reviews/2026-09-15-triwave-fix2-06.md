## Applied corrections

### T1-16-1 / stale setup-core smoke gate

`launcher:setup-core` now re-reads the committed launcher state after the asynchronous automatic-mode authentication probe and before consuming the smoke gate. A concurrent startup migration, account transition, logout, or interaction-mode change can therefore invalidate the current smoke evidence before setup proceeds; the handler evaluates the current state rather than the pre-await snapshot.

### T3-12-1 / interaction-mode proof invalidation

Both main-process interaction-mode transition callers now invalidate account-bound proof before the transition begins:

- `launcher:setup-mcp` when its requested mode differs from the current mode;
- `launcher:browser-interaction-mode` after credentials are confirmed and before the mode operation starts.

Invalidation advances the existing proof generation and clears MCP proof, browser smoke proof, setup identity, and verification timestamps. A failed transition cannot leave the previous account/mode proof presented as current.

### T3-12-2 / failed selected-account connector check

The `launcher:account-check` IPC wrapper now records the selected account before the asynchronous check. If that check fails while the same account remains selected, it invalidates and publishes the global account-bound proof before rethrowing the original error. If the user has selected another account during the check, the failed old-account check does not erase proof belonging to the newer selection; the account-selection handler already invalidates proof when that transition begins.
