# Wave 2 final correction, lane 07 — account pool

Baseline `3a66157` plus the uncommitted wave 1 implementation. Changed only `launcher/electron/account-pool.cjs`; this report is the additional authorized path. No public ABI, account registry format, connector/model identity, Native4 or Zero Risk4 pin changed.

- **D05:** A disabled-account running same-trace continuation now skips fresh-turn admission only when its tab is automatic and its conversation key and connector exactly match the requested metadata. A pinned fresh lease still uses `eligible()` and fails on its original owner without moving affinity. Explicit retained requests still run `precheckRetainedTurn`; exact ready retained tabs keep their continuation rule.
- **D17:** User account/tab selection requests mark their order before awaiting host readiness. An older pending request cannot publish over a later selection request or turn reveal. Tab activation checks the original tab object after readiness. If activation or publication fails after selecting the account, the pool restores the owner's prior active tab where possible and restores the prior selected account/descriptor only while this request still owns the selection revision. A failure while restoring a tab is logged separately and does not prevent attempting account restoration. A later user selection is never compensated away.

Manual review covered the changed branches, `BrowserHost.selectTab` (which can mutate `selectedTabId` before a descriptor error), `exactRetainedTurnTab`/`precheckRetainedTurn`, registry synchronous persistence, and direct launcher IPC callers. Per user instruction, no tests, test files, typecheck, suite, benchmark, runtime, production action or commit were run. Parent owns the final shared focused cases.

Material limit: if the previous tab was concurrently removed, restoration falls back to home; if the registry/descriptor write or host restoration itself fails, best-effort rollback logs the failure and propagates the original activation error. Actual readiness and concurrent tab-close behavior remain unverified in a live account session.
