## Recommended adaptations

### 1. Finish removing remote status lookups from tunnel readiness — high value

Local `src/tunnel.ts:617–657` still calls `runtimes status <alias> --json` during setup readiness polling. `launcher/electron/runtime-supervisor.cjs:854–883` still uses it to discover the loopback health URL. This leaves those paths dependent on an optional remote control-plane lookup.

The supervisor's ordinary health polling already uses local inventory at `runtime-supervisor.cjs:674–685`; this is a residual gap, not an entirely missing architecture.

Upstream `src/tunnel.ts:358–402` selects the exact alias from local `runtimes cleanup --json` inventory. Upstream `runtime-supervisor.cjs:784–820` uses `runtimes list --json`, an exact alias match, and its health URL file for discovery. Both projects pin tunnel client 0.0.12.

Benefit: avoid false setup/recovery failures caused by the optional status API being slow or unreachable through a proxy while the local tunnel can be checked directly. This does not eliminate actual tunnel network requirements or prove public MCP reachability.

Adapt only these paths, retaining our AbortSignal propagation, deadlines, loopback validation, integrity checks and independent MCP transport checks. Preserve detailed status output as optional diagnostics rather than a readiness prerequisite. The existing local code documents cleanup as a dry run unless `--apply` is supplied; preserve that non-applying form.

### 2. Invalidate response cache when CSS visibility changes — high value

Local `src/adapters/chatgpt-web/browser-worker.ts:3977–4017` returns a cached response when its subtree MutationObserver key is unchanged. Upstream `browser-worker.ts:3753–3815` additionally records rendering dependencies and rechecks computed display/visibility/opacity before that early return.

Benefit: recognize an answer or completion control revealed through CSS animation or stylesheet changes without a DOM mutation. The code gap is confirmed; no live NEKODEX stuck-answer incident was reproduced in this review.

Port the small observer dependency change, preserving our newer answer/commentary classifier, hidden Electron-view semantics, cancellation and completion fences.

### 3. Expand localized stopped-status detection — high value for non-English ChatGPT

Local `browser-worker.ts:4367–4395` recognizes English, Simplified Chinese and French. Upstream adds `src/adapters/chatgpt-web/ui-labels.ts`, an exact observed-label table including Russian `Рассуждение остановлено`, Japanese, Korean and others, and passes it into the response observer.

Benefit: return the existing terminal error when ChatGPT stops reasoning in those languages instead of waiting for completion that will never appear. This is separate from launcher UI translation.

Preserve the local exclusion of answer text, commentary, code and quoted content. Do not use generic phrase matching across the conversation.

### 4. Explicitly cancel an expired automatic task before disposing of its tab — medium/high value

Local `launcher/electron/browser-host.cjs:1473–1485` removes expired automatic tabs directly. Upstream `browser-host.cjs:1388–1427` first cancels the exact runtime request, coalesces concurrent cleanup attempts, and verifies tab/trace/helper ownership before delayed removal. Cancellation failure retains the recovery surface for another attempt.

Adapt the reason forwarding through main, runtime supervisor and server together. Upstream carries separate bootstrap-timeout and heartbeat-expiry reasons and emits a nonretryable timeout error. Local cancellation infrastructure already exists at `runtime-supervisor.cjs:2178`, `src/server.ts:994`, and `turn-execution.ts:949`.

Important limitation: local `browser-worker.ts:5125–5126` already detects page closure, and `turn-execution.ts:344–349` records terminal outcomes. Therefore the source difference does not establish permanent stuck counters in NEKODEX. The improvement is explicit ownership settlement and better failure provenance.

Retain our manual-mode recovery branch, suspension lease refresh, bounded server request parsing, physical-settlement semantics, and delayed-removal identity checks. DEV lacks the production cancellation callback and needs an explicit decision if extending this behavior there.

### 5. Restore the original launch environment before startup Restart — medium value

Visible failure recovery already exists in `launcher/electron/startup-recovery.cjs:31–78`, with bounded cleanup, safe diagnostic categories, a Restart button, visible relaunch and unconditional exit.

The missing piece is upstream's original-environment capture/restore. Local `main.cjs:86` overwrites `CODEX_CHATGPT_WEB_HOME` and `CODEX_HOME`; `startup-recovery.cjs:68` relaunches without restoring their original values. On DEV retry, `profile.cjs:44–51` can then see identical production and DEV homes and reject the profile.

Add the narrow capture/restore hook to the existing recovery helper. Keep our bounded cleanup and privacy protections. This is a high-confidence source-level failure path, not a runtime reproduction.

### 6. Improve MCP diagnostic correlation — medium value, small internal change

Our content-free transport diagnostics already exist in `src/adapters/chatgpt-web/mcp-diagnostics.ts:14–60`. Upstream's `mcp-observation.ts` contributes useful refinements:

- Mark duplicate in-flight request IDs uncorrelated instead of overwriting the earlier receipt (local lines 29–32).
- Report tracking-limit overflow and transport closure rather than silently evicting/clearing pending records.
- Use monotonic elapsed timing rather than Date.now differences.
- Include process identity when aggregating logs.

Benefit: avoid misleading evidence when diagnosing missing tool responses. This does not itself fix upstream tool rejection or prove execution success. No connector-generation change is needed; retain payload-free logging and the existing transport wrapper.

### 7. Show localized Pro-unavailable explanations — medium/low value

Local `src/adapters/chatgpt-web/pro-retry-hint.ts:4–18` only accepts the English `Try again after ...` sentence. Upstream `browser-worker.ts:210–241` accepts bounded text from the explicitly linked visible tooltip on a disabled Pro row.

Benefit: expose ChatGPT's own localized explanation rather than a generic unavailable error. Adapt the bounded tooltip behavior while retaining our stronger exclusion of conversation/composer content and optional-failure handling. Do not infer reset times or hide usage-limit warnings.

## Secondary additions and decisions

1. **Traditional Chinese and Korean launcher UI:** genuinely missing. Local `launcher/src/types.ts:1`, `i18n.ts:1211–1215` and `electron/state.cjs:64` support en/zh-CN/ja. Upstream adds a shared language registry, native dialog text, and zh-TW/ko translations. Useful for broader distribution; lower priority for Alex's workflow. Translate our NEKODEX-only account/settings flows too. Upstream does not add Russian launcher UI.
2. **Release download-link consistency check:** upstream `scripts/check-version.ts:38–44` checks versioned download links in localized READMEs. Our checker stops short of that. Adapt to NEKODEX asset naming and the actual supported platforms; do not paste upstream repository/asset names. Useful small release-maintenance improvement.
3. **Non-Pro Extra High context sizing:** local `chatgpt-web-models.ts:144,179` treats observed Extra High as sufficient for Pro-class limits (111,193 context / 95,000 compaction in the standard path); upstream uses non-Pro medium/high limits (90,000 / 80,000) when Pro is unavailable. Consider conservative limits for a genuinely non-Pro account, but UI absence of Pro can also reflect exhausted Pro availability. Source alone does not establish account entitlement or actual ChatGPT limits. Separate entitlement from current availability before changing policy; do not market this as free context expansion.
4. **Decoded JSON-value history scrubbing:** upstream parses context JSON and scrubs string values, avoiding accidental property-name rewrites. Local currently replaces across serialized JSON. The algorithm is a worthwhile precision improvement, but preserve our six broker capability kinds and distinguish native tool-call IDs. A wholesale replacement with upstream's three-kind regex would lose local coverage.
5. **README redesign and upstream branding:** no functional port recommended. Our repository has its own branding, release downloads and additional product features.

## Implementation recommendation and boundary

Use a selective adaptation, not a full merge or application replacement. The substantive upstream changes sit in one mixed commit, while NEKODEX has account affinity, capacity controls, a newer connector generation, additional lifecycle safeguards and its own release/update architecture that must survive.

Suggested order: tunnel readiness and CSS observation; localized stopped-status handling; explicit automatic expiry cancellation; DEV Restart environment; MCP diagnostics and localized Pro explanation. Add translations and release-link checking when distribution polish is the objective. Treat context-limit policy and decoded history scrubbing as separate scoped decisions.

Expected outcome is improved reliability and diagnosis in specific failure paths. No throughput gain, additional account quota, guaranteed context capacity, universal compaction fix, or resolution of upstream safety rejections was measured or established. No changes recommended here have been implemented by this review.
