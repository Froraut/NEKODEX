## Change

Fixed the remaining ownership interaction in `tunnelCommand` status exit handling.

When the configured owner is the embedded launcher, `tunnel status` now bases its exit result on tunnel runtime health and does not fail solely because the independent launchd service status probe throws. The service probe is still attempted and its error remains visible in the emitted `service.error` JSON field. A launcher-owned healthy runtime therefore remains a successful status result even when the irrelevant legacy OS-service probe is unavailable.

For terminal-owned configurations, service probe failure and a non-running service still fail the command. Start/restart and stop exit behavior remains unchanged.

The existing wave 1 behavior was retained:

- tunnel runtime probe exceptions are converted into a failed runtime status;
- tunnel service probe exceptions are converted into a structured service error;
- status JSON is emitted before the failing exit code is set;
- service ownership remains distinct from launcher ownership.
