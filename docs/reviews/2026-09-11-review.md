# Reliability, security, and usability review

Date: 2026-09-11. Baseline: upstream v5.0.6, commit `e85e369`.
Maintained fork: [Froraut/codex-chatgpt-web](https://github.com/Froraut/codex-chatgpt-web).

## Scope and conclusion

The review covered launcher authentication and recovery, Electron IPC, HTTP request boundaries,
credential handling, response streaming, compaction/shutdown ownership, dependency advisories,
updates/installers, onboarding, accessibility, localization, and release configuration. It was
prompted by observed macOS sign-in failures: an authentication popup constructor exception,
blocked navigation, and a passkey button that remained attached to an unfinished embedded login.

The fork fixes the concrete bugs below and adds regression coverage. This is a bounded source
review, not a claim that every possible defect has been found or that the app is risk-free.
Severity reflects practical impact and stated prerequisites. A dependency advisory or missing
defense is not automatically a proven exploit. No real account credentials, browser sessions,
private logs, prompts, or customer data are included in this repository.

## Fixed findings

| ID | Priority | Problem and consequence | Fix and evidence |
| --- | --- | --- | --- |
| AUTH-01 | High reliability | Electron can call `createWindow` without a guest `WebContents`. Passing explicit `undefined` into `WebContentsView` caused the observed uncaught exception. A constructor-only fallback would still leave a blank page. | Create a sandboxed guest in the owned partition only when needed; explicitly load the requested URL with the provided navigation metadata. Preserve supplied guests and inherited sandbox restrictions. Unit regressions plus the offline real-Electron popup smoke cover both branches. |
| AUTH-02 | High reliability | `Use passkey` returned the existing embedded login promise, so it never opened Chrome until that login timed out. | Abort and await the embedded attempt before starting the explicit Chrome passkey flow; deduplicate repeated requests and release locks after failure. Tests cover pending polling and pending probes, retry, and single browser ownership. |
| AUTH-03 | Medium reliability | A delayed page-load authentication probe could overwrite a newer imported session with stale signed-out state or close a replacement popup. | Session generations and captured view identities invalidate old results after every asynchronous probe/navigation boundary. Deferred-response regressions verify the newer session and popup survive. |
| HTTP-01 | Medium security | The loopback listener accepted foreign/opaque browser Origins, rebinding Host values, and safelisted non-JSON content types on JSON API routes. Isolated requests reached the adapter with HTTP 200. | Validate exact loopback host/port, Origin, Fetch Metadata, and JSON media types before dispatch. Native no-Origin clients and lifecycle bearer checks are preserved. Mock-adapter regressions prove rejection before execution. Browser local-network restrictions may also constrain exploitation; no real-browser account attack was performed. |
| HTTP-02 | Medium resource safety | Encoded input and zstd output were fully allocated before checking nominal 64 MiB/128 MiB limits. | Incremental encoded reads cancel over-budget sources; native zstd decoding enforces `maxOutputLength` while decompressing. Tests cover unknown-length input, unread cloned branches, split UTF-8, and a small compressed input expanding above 128 MiB. Total process memory also includes parser/decoder overhead. |
| HTTP-03 | High reliability | Integration of orderly shutdown exposed an incomplete-upload hang: waiting for HTTP cleanup cannot finish if a body reader ignores cancellation. | Make JSON and native raw/multipart readers abort-aware, discard unused clone branches, and refuse late dispatch after cancellation. Real local TCP tests leave uploads incomplete on Responses, search, and image-edit routes, then verify signal shutdown terminates them. |
| LOG-01 | Low security | Safe-log export relied on prior producer sanitization. Opaque credentials under nested sensitive keys could survive in legacy or malformed log records. | Independently redact credential-shaped keys during export, including nested arrays and objects. Synthetic raw/rotated-log regression verifies redaction and preservation of the source logs. |
| IPC-01 | Low hardening | IPC wrappers lacked an explicit check for the exact launcher renderer and its top-level frame. No hostile caller was demonstrated under the existing isolation/CSP/navigation controls. | Restrict launcher IPC and window controls to the expected main renderer/frame; test permitted and rejected callers. This is defense in depth, not a claim of a previously demonstrated remote execution exploit. |
| RUN-01 | High reliability | Non-streaming responses filled a bounded event queue before collecting it. Large output overflowed; error handling tried to enqueue another event into the full queue. | Collect while producing; maintain the bound and deliver failures out of band so overflow is explicit and adapter work is cancelled. Regressions cover large healthy output, synchronous saturation, streaming, and cancellation. |
| RUN-02 | High reliability | Structured compaction owners could be absent from drain/health accounting. Shutdown could report idle while compaction still owned abortable work. | Include active compaction owners in the idle barrier and service negotiation; revoke them during shutdown. Tests verify busy shutdown rejection and abort propagation without touching a real integration. |
| RUN-03 | Medium correctness | Non-streaming responses could report `completed` after content filtering or adapter EOF without a terminal event, unlike SSE. | Preserve incomplete reasons consistently in both response formats and prevent incomplete output from looking successful. Targeted bridge regressions cover the terminal classifications. |
| UPD-01 | High fork reliability | Hardcoded upstream update URLs could overwrite a fork's changes. | Pin update ownership in the packaged manifest, point installer defaults and source metadata to this fork, reject wrong-origin asset URLs, and handle a fork with no releases without falling back to upstream. |
| UPD-02 | Medium resource safety | Update assets had no byte cap; inactivity timeouts did not prevent a slow endless download. | Cap assets at 1 GiB, verify exact declared byte length, enforce overall metadata/download deadlines, and remove partial files while preserving pre-existing destinations. Tests cover oversized, truncated, stalled, and wrong-origin downloads. |
| DEP-01 | High dependency advisory; application reachability not established | The locked launcher build dependency `js-yaml` and transitive Hono components had current advisories. The app uses MCP stdio, not Hono's HTTP/SSG integrations. | Pin `js-yaml` 4.3.2 and `hono` 4.13.5, refresh the two lockfiles, and verify frozen installs, audits, MCP protocol compatibility, and build tooling. |
| UX-01 | Medium usability | Onboarding required opening GitHub and X before the app could be used. | Make those links optional in both the UI and main-process validation; preserve upstream attribution. |
| UX-02 | Medium user control | New installs enabled OS auto-start before an explicit settings choice. | Default new profiles to auto-start off; preserve already saved preferences. |
| UX-03 | Medium recovery | A failed initial snapshot left a permanent loading screen because the error UI was unreachable. | Show the startup failure with a Retry action; retain errors when retry fails. |
| UX-04 | Medium usability/accessibility | Navigation controls did not reflect login ownership; passkey flow guidance could be hidden behind the browser; tab controls lacked keyboard activation. | Publish authoritative login/lock state, show a persistent Chrome sign-in guide, use an explicit import button, improve error copy, and add keyboard tab selection. English, Chinese, and Japanese remain aligned. |
| CI-01 | Low hardening | Platform release-build jobs received repository write permission while installing and executing dependencies. | Default release jobs to read-only repository access; grant write access only to the publication job. |

## Remaining improvements, in priority order

1. **Explicit remote-content permission policy.** The remote Electron session has no product-specific
   permission request/check handlers. Define which capabilities are necessary, validate requesting
   origin/frame, and deny or prompt for everything else. Test clipboard, media, notifications,
   storage access, identity-provider login, and native OS consent before changing this policy.
   No attacker-controlled landing page or actual sensitive-data access was established in this review.
2. **Signed, independently authenticated releases.** SHA-256 checks detect corruption and mismatched
   assets, but a manifest downloaded from the same release does not authenticate a compromised
   publisher. Add release provenance, pinned action revisions, Developer ID signing/notarization,
   and equivalent Windows publisher signing. Existing ad-hoc signing is not notarization.
3. **Transactional update recovery.** Validate staged bundle identity/version and preserve a previous
   usable app until the new process signals readiness. Exercise failure at every replacement and
   relaunch step on all supported operating systems. Current checksum/size checks alone do not
   prove that the installed app will start.
4. **Real account and platform acceptance.** Re-run ordinary login, macOS passkey/Touch ID, session
   persistence, browser smoke, and an installed Codex/MCP task, including cancellation and compaction.
   Test Windows pipe ACLs, macOS x64, and Linux package startup on their actual platforms. Mock,
   DEV, renderer, and offline Electron tests cannot prove these outcomes.
5. **Browser UI drift monitoring.** Add sanitized, versioned DOM fixtures and an opt-in account-bound
   acceptance process for upstream ChatGPT changes. Keep strict model selection and explicit
   errors; avoid silent fallback or repeated sends as a recovery mechanism.
6. **Reduce architectural concentration.** The large server, browser-host, and renderer modules mix
   lifecycle, protocol, UI, and persistence responsibilities. Extract small units at stable ownership
   boundaries as fixes require them, with behavioral contract tests. A broad rewrite would add risk.
7. **Clarify manual mode naming.** The inherited "Zero Risk" name only distinguishes manual browser
   interaction. It does not remove account, MCP tool, local-session, network, or policy risk. A future
   UI rename to "Manual mode" should be coordinated across docs, model labels, and migrations.
8. **Fork release identity.** Source metadata and update origin are fork-specific; the inherited app
   identity/profile remains compatible. Decide whether a distributable fork should replace upstream
   or coexist under a distinct bundle identity before shipping installable binaries.
9. **Durable import phase and resource budgets.** Screen changes now preserve passkey import state,
   but a complete renderer/process reload still needs a public runtime phase to reconstruct it.
   Add byte budgets for replay journals/helper buffers and consider a configurable total response
   budget: event counts and request payload limits do not bound all process memory. Explicitly
   dispose server signal handlers for applications embedding multiple server lifecycles.

## Validation and limits

Focused regression suites were run for each changed behavior before integration. A real Electron
41.10.7 smoke loads both missing-guest and supplied-guest popup surfaces in an isolated, sandboxed
session. Credential-free renderer fixtures exercise onboarding, login controls, passkey guidance,
startup retry, and localization. Dependency audits use the updated frozen lockfiles.

The repository's required integrated `bun run verify` gate covers version consistency, both audits,
core and launcher typechecking/tests, the renderer build, runtime bundling, third-party notices,
and a relocated runtime smoke.

**Integrated validation passed on macOS arm64 with Bun 1.4.0:**

- Core: **734 passed, 0 failed, 1 skipped**, 3,755 assertions across 55 files.
- Launcher: **342 passed, 0 failed, 1 skipped** across 343 cases.
- The skips are a Windows path-namespace test and a Linux AppImage process-identity test on macOS.
- Both frozen dependency graphs audited clean: **106 core packages and 351 launcher packages**.
- Core and launcher TypeScript checks, version consistency, and Vite production build passed.
- Runtime bundling and third-party notices succeeded; the runtime reported
  `RELOCATABLE_RUNTIME_SMOKE_OK` after relocation.
- Separate real Electron 41.10.7 checks passed for both auth-popup guest branches and for allowing
  the main renderer while rejecting a child frame at the IPC boundary.
- Credential-free renderer checks and reproduction steps are recorded in the
  [UI fixture evidence](../../launcher/tests/fixtures/README.md).
- Release YAML parsed successfully with write permission limited to the publish job.

The final post-gate changes only record these results in documentation and receive link and
whitespace checks. The runtime sources are the same ones validated by the integrated gate.

Reproducible focused commands (Bun 1.4.0):

```bash
bun install --frozen-lockfile
bun install --frozen-lockfile --cwd launcher
node --test launcher/tests/authentication-lifecycle.test.cjs
node --test launcher/tests/update.test.cjs launcher/tests/logging.test.cjs
bun test tests/server-http-security.test.ts tests/http-body.test.ts
# On macOS with the launcher dependencies installed; local/offline only:
cd launcher
env -u ELECTRON_RUN_AS_NODE ./node_modules/.bin/electron scripts/smoke-auth-popup.cjs
```

Source publication does not update an already installed app. No live ChatGPT/MCP execution,
production-profile migration, notarized binary release, or upstream maintainer acceptance is claimed.
