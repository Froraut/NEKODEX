## Narrow #431 follow-up implementation

The `probeAuthentication` correction in `launcher/electron/browser-host.cjs:2844-3040` now distinguishes a **trusted JSON session verdict** from unavailable inspection. At `:2914-2957`, a redirected endpoint, non-2xx response (including 401/403), non-JSON response, malformed payload/expiry, JSON `error`, timeout, or fetch failure remains `unavailable` with a safe reason. Only a successful JSON object from the exact `/api/auth/session` endpoint with no error and either no user or a known expired timestamp becomes `rejected`; a present user with no error and valid expiry remains authenticated. The nested block indentation was corrected. A protective HTML page and an application-level transport error can no longer be mislabeled as a confirmed logout.

The outer branch still requires a loaded Temporary Chat composer and an authenticated session before publishing `authenticated: true` (`browser-host.cjs:3009-3040`). An unavailable probe publishes an error rather than “Sign in to ChatGPT” and, when `forSetup` is true, throws the safe inspection reason; `launcher/electron/main.cjs:745-755` now requests that setup-specific probe and retains its authentication gate. No live proxy, account or connector recovery is claimed. The combined host diff also contains a separate lane-03 descriptor/selection fix; this section describes only #431.
