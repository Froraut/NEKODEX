## R2-16-1 — Same-process snapshot continues to claim invalidated smoke evidence (new path, shared root with R1-16-1)

**Trigger:** A production launcher passes `launcher:browser-smoke` during the current app session, then a managed-runtime upgrade migrates its connector without quitting that Electron process. `launcher/electron/main.cjs:609-614` saves the pass and sets `smokePassedThisSession = true`; migration clears `browserSmokePassed` and `browserSmokeVersion` in persisted state at `:1332-1357`, but does not clear the session flag. The direct `launcher:snapshot` IPC response computes `smokePassed: smokePassedThisSession || smokePassedForCurrentVersion(stateStore.read())` at `:455-456,475-493`. Consequently even a fresh snapshot after migration returns `smokePassed: true`, and initial `App` hydration copies it into Setup (`launcher/src/App.tsx:157-166,1452-1460`). Remounting the renderer in the **same main process** does not repair this claim.

**Consequence:** A new renderer can label the smoke row passed after backend migration deliberately invalidated persisted evidence. This is the same readiness-evidence failure as R1-16-1 with an additional backend snapshot route, not a second independent functional defect or evidence that an IPC call skipped settlement.

**Counterevidence/limit:** On a new Electron main-process launch, `smokePassedThisSession` initializes false (`launcher/electron/main.cjs:113`), so the cleared persisted fields yield a false snapshot unless another smoke pass occurs. The setup row calls this check optional once core setup is complete (`launcher/src/App.tsx:1452-1457`); backend setup only requires smoke while core setup is incomplete (`launcher/electron/main.cjs:758-765`). This does not show that tool execution or the setup API bypasses a mandatory smoke gate. The trace requires a real same-session smoke pass followed by migration; no live reproduction was attempted.
