# Python skill environment development verification — 2026-10-19

This report covers the explicit offline selected-wheel environment implementation
described in the [contract](../design/python-skill-environments.md). Source,
focused fixtures, actual GUI/model outcomes and installed delivery remain separate
evidence. This is not universal dependency support or completion of P16/P17/all44.

## Implemented connected boundary

One core-owned store shares the executor's exact admitted Apple Python runtime.
Local Review snapshots selected canonical wheel bytes and validates the complete
declared distribution closure; separate Prepare publishes an immutable ID-bound
environment. No pip, resolver, network, build hook or package import runs during
preparation. Attach separately binds the environment to a task generation; each
Python tool call still uses its workspace grant and ToolJournal approval.

The store checks ZIP paths/types/budgets/CRC, wheel metadata/tags and RECORD hashes,
locks mutations with a persistent Darwin advisory inode and retains signed action,
manifest and pending-publication evidence. Unknown preparation is not replayed:
explicit reconciliation verifies an existing exact result or remains held.
Public metadata/errors omit private roots. Runtime bootstrap and Seatbelt retain
the established isolated Python/fork/exec/network boundaries; environment data
adds read authority only, with immediate dispatch revalidation.

PEP 440 uses pinned maintained parser 5.0.1 plus the scoped normative exclusive
comparison adapter. PEP 508 markers/extras/direct URLs, native/data-scheme/startup
payloads, source/build inputs and unsupported wheel features remain explicit
refusals. Shell, broader dependency/runtime formats, network grants, other OSes
and installed packaging are open scope.

## Failures corrected before crediting acceptance

The first store run reached a new protected-header canonical-path prerequisite
failure before the environment boundary. Its macOS results were invalidated,
including a negative archive case that appeared to pass only because runtime
admission had failed earlier. Runtime admission was corrected to pin the actual
canonical protected header/link identity; the fixture now establishes runtime
admission before any negative assertions. All four macOS cases were rerun; only
the unrelated passive-case PASS was reused.

An overlap-refusal attempt also exposed an empty run directory that could mask
the intended later refusal through retained-owner handling. The overlap check was
moved before run-directory creation, and the affected kernel import/admission
case was rerun. A refusal at the wrong earlier boundary is not credited as proof
of the intended containment or admission check. TypeScript narrowing corrections
preserved throw semantics rather than weakening runtime validation.

## First real attempt and readiness correction

The first task had one UI Run ending **NOT_SENT**, zero actual Native offers and
no output. It was stopped at generation 2 and its old Native owner was closed.
The generic receipt does not establish an exact underlying failure code; none is
inferred here.

A separately observed readiness gap was corrected: models could be advertised
before owned process prestart, while the five-minute admission freshness window
could expire during a roughly twelve-minute user preparation flow. The fix warms
the owned process before advertising readiness while preserving freshness,
account/lease authority and exact configuration/executable pins. In the successful
new flow the prepared owned process existed before Run with zero turn bindings;
no model offer was spent by preparation. The earlier NOT_SENT task was not replayed.

The first source CI run exposed an outdated persistent-conversation fixture:
it supplied an account context before preparation, so ten cases refused at the
new readiness prerequisite. The fixture now prepares initial and restarted
contexts before publication. Only those ten affected cases were rerun locally;
production readiness guards and the accepted macOS runtime were unchanged.
