## Handoff

The launcher now owns an account-proof generation in `main.cjs`. Positive browser smoke and MCP verification capture the generation, browser interaction mode, and `setupIdentity(...)` value before their asynchronous work. Before publishing a positive result, each handler re-reads the current state and browser/runtime identity. A result is discarded when the generation, mode, identity, or required core setup is no longer current.

Account selection and logout retire account-bound proof before their asynchronous browser operation starts. Mode changes retire the same generation before the mode transition. Runtime startup failure paths retire it before clearing setup state, and a managed connector migration retires it when its state update invalidates smoke/setup proof. Existing connector names, Native4, Native4 DEV, ZeroRisk4, and public tool/API contracts were not changed.

## Limitations

This is source-level lifecycle protection. It does not prove live account switching, ChatGPT connector approval, account-side picker rendering, completed native/browser turns, or runtime timing. The parent owns the final focused verification, bounded to at most 60 seconds and 10 scenarios. No ABI or connector identity changes are included.
