## New concrete finding (1)

**R2-2-1 — gateway-only `shell_command` silently drops requested command options.** Trigger: the outer turn has freeform `exec`, no bare direct `exec_command` or `shell_command`, and its nested registry has `shell_command` but not `exec_command`. A `codex_exec` request supplies `tty: true` and/or `max_output_tokens`. In `mcp-server.ts:649-670`, `execCommandArguments` includes both fields, but `shellCommandArguments` omits them. The explicit incompatibility check at `:678-680` runs only when `exactTool` finds a direct card (`:671-682`). The gateway branch at `:684-693` proceeds without that check; its program selects nested `shell_command` at `:445-452` and dispatches the already stripped shell arguments. Consequence: the call can execute successfully without the requested TTY or output limit, while the caller sees no rejection and may rely on the missing option. Counterevidence/boundary: a direct bare `shell_command` rejects these fields; a gateway containing both native command names or neither fails before dispatch (`:447`). No live nested registry was exercised, so this finding establishes a deterministic source-path defect under the stated registry shape, not its frequency in the current account. The first-wave lane 2 statement that `shell_command` rejects unsupported TTY/output (`review1-02.md:11`) is too broad: it holds for direct dispatch only. Lane 1 explicitly scoped that assertion to direct dispatch (`review1-01.md:16`).

## Repeated candidate, no new ID (1)

**R1-2-1 remains conditional, not a fresh R2 finding.** The nested gateway `execGatewayResultProgram` (`mcp-server.ts:334-351, :437-453`) emits result content without its `isError` flag; the outer `asMcpResult` (`:229-239, :566-573`) preserves only the gateway's own returned flag. The broker's direct result contract does support `isError` (`turn-broker.ts:24-29`; `index.ts:246-256`), and direct structured command results preserve it (`mcp-server.ts:671-682`). Counterevidence: a nested command throwing rejects the generated program, and no observed native command result shape establishes that `isError: true` is returned rather than thrown in this specific nested runtime. Do not promote the first-wave conditional consequence to a confirmed live failure.

## Rejected first-wave generalization / optional boundary (1)

The first-wave lane 2 claim of uniform `shell_command` option rejection is rejected for the gateway branch by R2-2-1. A separate **optional mapping concern**, not counted as a defect: `codex_exec.yield_time_ms` is forwarded as `shell_command.timeout_ms` (`mcp-server.ts:635, :666`). If a future shell card defines `timeout_ms` as execution deadline rather than first-output yield, a request expecting a short yield could terminate a longer command. The exact shell card semantics and its actual use were not established here; no runtime failure follows solely from the differing names. Likewise missing direct IPC in this module does not imply missing settlement: `withClaimedTurn` retires broker activity in `finally` (`:514-528`), and `invoke` sends a broker release on transport failure (`:574-605`).
