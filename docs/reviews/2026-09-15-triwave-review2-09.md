## New conditional source-path finding

**T2-9-1 / P2 — successful nested gateway results lose distinct structured data.** Trigger: the outer Codex turn advertises freeform `exec` and a desired native tool is available only through its nested `ALL_TOOLS` registry. That tool returns a successful MCP-like result such as `{content:[{type:"text",text:"created"}], structuredContent:{id:"abc",state:"ready"}, _meta:{receipt:"..."}}`, where structured fields are not duplicated in text. `execGatewayProgram` and `execCommandGatewayProgram` both call `execGatewayResultProgram` ([`mcp-server.ts:374-383`](/Users/alex/Dev/nekodex/src/adapters/chatgpt-web/mcp-server.ts:374), [`:451-463`](/Users/alex/Dev/nekodex/src/adapters/chatgpt-web/mcp-server.ts:451)). Its success branch emits `result.content` recursively but never emits or encodes `result.structuredContent` or `_meta` ([`:343-356`](/Users/alex/Dev/nekodex/src/adapters/chatgpt-web/mcp-server.ts:343)). The outer `exec` response, broker conversion, and `asMcpResult` can only relay fields present in that outer response ([`mcp-server.ts:576-583`](/Users/alex/Dev/nekodex/src/adapters/chatgpt-web/mcp-server.ts:576), [`index.ts:227-256`](/Users/alex/Dev/nekodex/src/adapters/chatgpt-web/index.ts:227)). A caller using `codex_tool_call` or `codex_exec` can receive a successful text answer without a native receipt or structured return value. With `content:[]` and nonempty `structuredContent`, the emitter produces no content at all.

This is a separate successful-result path from adjudicated **D08**, which concerned a nested returned error being reported as success. The four-wave R1 lane 2 text incidentally said the old emitter discarded `structuredContent`, but its candidate, adjudication, and D08 correction targeted only `isError`; the successful, distinct-data consequence was not an accepted defect. The first-wave lane 9 statement about direct structured relay is correct for a *direct* broker result ([`mcp-server.ts:229-239`](/Users/alex/Dev/nekodex/src/adapters/chatgpt-web/mcp-server.ts:229)) and does not establish relay of a nested result through generated `exec` JavaScript. The D08 error branch serializes structured **error** detail into a thrown message ([`:337-342`](/Users/alex/Dev/nekodex/src/adapters/chatgpt-web/mcp-server.ts:337)); it does not repair this success branch.

Counterevidence and limit: if the nested tool's `content` already contains a faithful JSON copy of its structured fields, `index.ts` can reconstruct structured content from that text and the visible data is not lost. No live account result shape was sampled here, so this report proves the conditional branch and consequence, not that a currently installed nested tool uses distinct structured fields. A correction should preserve content/media and serialize successful structured data through the available `exec` emission surface without changing MCP tool registrations or public connector ABI. If the parent has room in its single focused pass (<=60 seconds, <=10 scenarios), one synthetic distinct-text/structured-result case would resolve this boundary; this lane did not run it.
